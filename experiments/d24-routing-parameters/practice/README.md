# D24 路径参数实验（全部模拟）

Python 3.10+。默认只用标准库重放已保存记录，不调用生产系统，不派车。

```
python test_run.py
python run.py --output-dir replay
```

真实重新求解（建议虚拟环境）：
```
python -m pip install -r requirements.txt
python run.py --solve --output-dir new-run
```

`outputs` 是发布证据，不允许通过 CLI 覆盖。新运行的路线、状态和耗时可能不同。14 个配置各运行一次，不能当成多次统计基准。求解时间参数是上限而不是承诺耗时。

## 输入来源及协议

- inputs/apparel.json、hewei_extension.json 原样取自 https://12lab.cn/downloads/d22-capacity-routing-practice.zip 。11×11 曼哈顿米矩阵、10点每点2箱、2辆12箱车。
- inputs/apparel_tw.json、hewei_tw.json 来自配套 D23 四点输入。分钟矩阵、卸货时间、服务开始窗口、出发与回仓约束均为模拟。
- 业务情景：12箱×0.8=9.6，12箱×1.2=14.4，约定容量向下取整为9/14箱，实际变化为-25%/+16.67%，不是精确±20%。需求、车辆数、路线目标不变。
- 算法配置：PATH_CHEAPEST_ARC + GUIDED_LOCAL_SEARCH，所有实验一致。D22 发布运行用 GREEDY_DESCENT；本篇重新跑基准，不把与D22的差别归因于容量。
- 容量实验均1秒；相同基准输入另运行5/10秒。1秒基准记录复用作时间实验起点。
- 时间窗只改变指定点2的闭区间为[510,510]，允许等待，固定08:00出发、10:00前回仓。窗口约束开始服务，不是结束卸货。
- 默认不可丢点、不可拆单，每车一趟，允许闲置车[0,0]。目标只是总米数，无车辆固定成本、司机费用或逾期罚金。

## 文件与边界

run.py 包含求解适配与独立排程验算。d21_checker.py 来自 D22 包；为 D23 显式矩阵跳过缺失的坐标元数据交叉验证，其余覆盖、容量、米矩阵校验保留。check 不依赖 OR-Tools 的 CumulVar 或打印结果，从原始输入重新算。

每个输出保存规范化输入 SHA256、配置、版本、原始状态、路线、目标值、独立校验指标和模拟声明。无解路线用 null，CSV 中不适用项为空，不能填0。容量9箱时18<20，可独立证明不可行，即使求解器仅报告超时。其余没有返回路线的记录不能自动判为不可行。

总等待按本地最早服务排程重算，仅是所返回顺序的可行排程指标，不是被优化的目标，也不声称与求解器内部等待安排完全相同。每次求解只运行一次；墙钟耗时受机器负载、版本影响。

两案都是教学模拟。匿名服装不含真实工厂、订单或收益；禾味十点是独立教学扩展，不能当成原2店、8SKU、14天数据的直接推演。
