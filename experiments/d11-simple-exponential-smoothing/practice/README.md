# D11：简单指数平滑实践包

Python 3.10+，仅标准库。在本目录执行：

```bash
python -m unittest -v
python run.py
```

本包为教学模拟。禾味虚构背景为2店、8个食材SKU，计算对象仅A店SKU01，公斤/日。匿名服装标签是终端订单需求，件/日，不是生产需求。两案例不混合评分。

首周2店、8食材SKU的14天样本用于数据和指标学习；预测沿用D9扩展的180天模拟序列，本包仅使用前140天。数据从D10前140天开发CSV逐字节复制，哈希与D9-v1相同；`source_manifest.json`保留两文件SHA-256。第1—112天训练，113—140天验证。D9已展示原测试汇总；第141—180天不是未触碰盲测，本包不包含那些标签，当前运行入口只读取前140天开发CSV并评分验证段；包内容本身不能证明以往会话是否访问过任何文件。没有联网下载数据步骤。`source_manifest.json`中的原D9 ZIP哈希是沿用的来源声明，本轮未独立核验该ZIP；已核验的是当前两份开发CSV的实际字节。

SES使用第一个观测初始化，固定α=0.2/0.5/0.8；水平只随已观察需求更新；一步预测用前一天的水平，同一起点五步均为该起点水平。周期7季节性朴素基线使用相同目标。验证期间允许起点前已经观察到的验证需求进入状态；不在每日临时重选α。

每个案例每种方法28个一步目标、24个完整五日窗口。五日窗口起点112..135，最后目标为140，不跨分块。MAE按案例分别算，五日指标先求实际合计与预测合计的绝对差，再平均；重叠窗口不独立。没有宣布最终模型或真实业务收益。

## 输出与核验

`run.py`先核验源文件字节，再重建`results/`下六个CSV/JSON数据产物（旧文件不会删除）：

- `daily_predictions.csv`：224行，含origin、target、actual、prediction、absolute_error。
- `five_day_windows.csv`：192行，含每个未来步的预测和实际、合计及合计误差。
- `levels.csv`：840行，表示观察当日需求后的水平；不能作为当日提前预测评分。
- `validation_summary.json`：完整精度分数及数据哈希。
- `origin112_examples.json`：第112天固定起点的各方法五步值。
- `manual_oracle.json`：独立字面手算预期。[10,20]、α=.5 得15；[10,20,10]的三个α得11.6、12.5、11.6。

`policy.json`记录规则，不是用于任意调参的配置接口。`baseline.py`实现输入校验和模型，`test_baseline.py`的27项测试覆盖手算、未来污染、固定起点、α端点、日期、物理空行及CSV坏输入，并用展开权重加Fraction算术独立核对全部预测、五步输出和分数。

CSV入口遵循标准库约定，跳过没有任何字符的物理空行；仅含空格的行视为不完整数据记录并报错。允许物理空行不允许缺失某一天：日期连续性仍须满足。代码支持零需求和α端点，拒绝缺失、负数、非有限值、错误日期与混合实体。`forecast_at`先截取起点前的记录，再校验可见历史；即使未来记录损坏，也不得改变既有起点预测。完整文件入口仍会校验整个已提供开发集。

`MANIFEST.sha256`记录随包文件字节（不含自身）。重算后六个数据产物应保持一致。测试日志用`python -m unittest -v`重新获得；各机器运行时长可能不同。

## 数值边界

这是非负有限日需求的教学实现，使用Python浮点数。生产系统仍需定义数据可用时点、异常和缺货口径、历史修订、冷启动与业务可支持的数值范围。仅一个观测能初始化，不表示足以支持可靠预测。本包没有概率区间或库存/排产优化器。
