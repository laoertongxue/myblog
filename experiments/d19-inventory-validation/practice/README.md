## 数据与边界

两份data CSV逐字节复制D13开发数据，SHA-256在run.py与manifest.json中固定。禾味为虚构两店八SKU背景，只计算A店SKU01，单位公斤；服装为匿名协同场景的单成品库存节点，单位件。需求、库存、订单和结果全部模拟，公斤与件不可合并评分。服装需求不等于排产量。本沙盘按整数公斤/整数件处理，不代表现实中的最小包装。

训练1—112日，仅此区间估误差尺度和Q；验证113—140日用于18个候选的开发排名。D9测试汇总已经公开，开发数据也多次查看，因此不是新盲测、无偏泛化证明或真实经营结果。没有读取141—180标签，亦未运行D20。

## 先写规则再回放

首次执行D19验证前先写定候选集合与排序规则。首轮验证完成后，D20库存计划从141—152日热身、153—180日评分，修订为153日直接以相同冻结初态起跑、153—180日全段评分。现版为D19-v2-reviewed-protocol，是这一修订之后的冻结版本，不是首次验证前原封不动的协议。候选、排序、需求与全部D19策略结果未变，详见REVISION_NOTES.md。本地文件没有独立可信时间戳，修订与哈希不恢复盲测资格，也不能证明不可篡改的事前注册。候选每案例9个：每日6个（Q两档、z三档），周期3个（R固定3、z三档）。模型固定为季节性朴素7日，从决策日日末已观测原始需求前缀生成固定起点预测；不把未来实际、销量、失销校正值或库存状态反馈给预测器。模拟假设缺货时仍完整观测外生原始需求，实际项目未必满足。

事件顺序：日初到货→原始需求履约→日末复核。失销不欠交，IP=现存+在途。t日末订货，t+L+1日初到，L=2。每天至多一单，到货不重复计入现存和在途，期末未到订单保留。

每日(s,Q)：每日日末检查，IP≤s_t则订固定Q一次，s_t=ceil(未来3日预测合计+z×训练H3累计误差RMS)。这里H=L+1=3是每日只检查一次的阈值结构：若推迟到t+1日末才下单，最早t+4日初到，因此t日末阈值覆盖t+1..t+3。不是连续复核直接代L=2的公式，不承诺任何服务概率。

周期(R,S)：R=3；验证复核113、116、…、140日末；S_t=ceil(未来5日预测合计+z×训练H5累计误差RMS)；复核时订max(0,S_t−IP)。保护期H=R+L=5，下一次复核订单t+6日初到，因此本次覆盖t+1..t+5。非复核日也输出当时预测阈值供诊断，但不下单。

RMS=sqrt(mean(累计实际−累计预测)^2)，不是去均值标准差。H3训练起点7—109（103个），H5起点7—107（101个），完整窗口均留在训练内。另报累计误差均值以显示偏差。重叠窗口非独立样本。z∈{0,1,2}只作缓冲倍数，不能解释为95%或其他正态服务概率。

Q=ceil(训练日均需求×2)或ceil(训练日均需求×4)，每案例固定两档。初始OH=ceil(训练日均×3)、初始在途为空，同案例9个候选完全一致。禾味OH78，Q52/103；服装OH316，Q211/422。两案例不可用绝对量横向比较。

每案例每策略分别按以下顺序择一并冻结，最终保留四套，不从两策略中二次择“冠军”：失销最少→平均日末现存最少→订单次数最少→完整参数canonical JSON字典序最小。不计成本、保质期、报损、服务承诺、产能、批量包装或随机提前期，不宣称经济最优。日末平均不是日内时间加权平均。fill_rate=履约量/需求量，零总需求时为空，不是周期服务率。

## 七日手算

output/manual_seven_days.json保留4张完整台账、订单事件和尾单。禾味沿用D16需求[7,9,8,4,5,6,3]、OH12、8公斤第2日初到；每日固定s10/Q6，周期固定R3/S20。服装沿用需求[5,8,4,7,3,6,2]、OH6、4件第1日初到；每日s8/Q6，周期R3/S18。两案例本次统一L=2，服装因此**不是复印D16的L=1结果**。首次复核均为第1日末。这些固定参数仅检验时序，没有用7日结果选择参数，也不混入开发验证。

## 输出

- ledger.csv：18候选×28天=504行，每行标案例、单位、参数标识、需求、履约、失销、到货、下单前/后IP与在途、日末现存、是否复核、阈值和订单到货日。
- order_events.csv：所有新增与到货事件，稳定订单ID；初始在途在手算JSON内显式记录。
- pending.csv：各候选第140日末有效尾单，未来日期不意味着读取未来需求。
- parameters.json：18套参数与相同初始状态；results.json：开发指标及策略内排名。
- training_errors.csv：408个仅训练块内的固定起点累计误差，含案例、单位、保护期、起点、目标起止日、累计实际/预测及误差。
- training_scales.json：H3/H5的RMS、ME、样本数和训练起点边界。
- frozen_config.json：四套冻结参数、初始状态、源哈希、协议哈希和未来计划。
- freeze_receipt.json：冻结配置、开发排名及协议SHA-256。manifest.json覆盖源、协议、代码、测试、说明和输出，检测漂移，不是外部认证或防攻击签名。
