# D10-v1 移动平均需求预测实践

**本包只做验证集比较，不做测试集评价。** 禾味是虚构餐饮连锁，服装案例为匿名生产协同背景下的终端订单需求模拟。所有数字均为教学模拟，不能解释为真实经营效果、补货收益或排产收益。

## 运行

Python 3.10 或更新版本，仅标准库，不需要安装依赖、Docker、网络或付费服务。在解压后的目录运行：

```sh
python -m unittest -v
python run.py
```

第一条运行程序正确性测试，不是评估封存测试集。第二条校验原始开发数据 SHA-256，再覆盖生成 `results/` 中的 CSV 和 JSON。程序没有下载、读测试标签、解封、训练复杂模型、自动选定最终模型或连接生产系统的入口。

## 计算口径

`baseline.py` 里的 `origin` 是一基的最后已知日。在这套从第 1 天开始的数据中，也就是已观测行数。第 T 天已经结束且需求已知，才可把它纳入预测 T+1 的窗口。

- **移动平均 MA(k)**：取最后 k 个已观测日的算术平均，k 只比较 3、7、14。
- **固定起点多步**：从同一个 T 预测未来 5 天，五个预测都等于该次均值；既不把未来真实值塞回窗口，也不把刚预测出的值递归塞回窗口。
- **周季节性朴素 SNaive7**：固定起点循环最后一周的逐日值，用同星期的上一周观测作基线。它保留一周的形状，不等于“最近七天平均”。
- **每天滚动一步**：预测第 113–140 天，共 28 次，起点第 112–139 天。第二天重做预测时，前一天已发生的真实需求允许进入新的历史。
- **滚动起点的五天累计**：起点第 112–135 天，共 24 个窗口，目标从 113–117 到 136–140，整个目标窗都在验证段内。每个窗口内部是固定起点，不提前引入该窗未来实际需求。
- **日 MAE**：28 个 `abs(actual - prediction)` 的平均，单位为 kg/day 或 pieces/day。
- **五日总量 MAE**：24 个 `abs(sum(actual_h1..h5) - sum(prediction_h1..h5))` 的平均，单位为 kg 或 pieces。它不是五个绝对误差之和，也不是把每天滚动重算的一步预测相加。

五日窗口彼此重叠，不是 24 次独立实验。不同指标可能偏好不同窗口；本包只给比较结果，不自动宣告一个最终模型，更不以验证排名替代测试性能或服务水平。

## 输入边界和测试

CSV 使用严格解析，未闭合引号或闭合后多余字符会明确报错。本实现遇到空历史、历史短于 k、非法 k/步长/起点、缺失字段、重复或缺日期、乱序、负值、NaN/Infinity、布尔值、混合实体会报错。合法零需求照常进入均值，不删除、不自动补非零。短序列不偷偷缩短窗口；缺失日也不悄悄补零。源 CSV 本身没有实体列，调用者显式提供其单一序列身份；文件与单位映射在 `policy.json`，不能拼接两份文件后当成同一条序列。

`test_baseline.py` 包含独立于生产预测函数的手算和 `Fraction` 有理数 oracle：

- `10,20,30` → 下一日 `20`；固定起点五日 `20,20,20,20,20`，累计 `100`。
- 历史 `1..14` → MA3 为 `13`，MA7 为 `11`，MA14 为 `7.5`，各自五步恒定。
- `2,4,6,8,10`、k=3 → 五步都为 `8`；拒绝错误递推得到的第二步 `26/3`，也不让未来实际 `0` 把第二步变成 `6`。
- 把起点后的数据改成极大值，预测仍等于独立手算期望；甚至起点后的非法行也不会被预测函数读取。
- 改动起点当天的已知需求，预测应相应改变，证明边界没有错误地排除该天。
- 用独立 CSV 读取和 `Fraction` 运算复算全部验证指标，不调用模型和窗口工具函数产生期望值。

这证明本小实验的实现符合明确口径，不证明实际业务数据已清洗完成，也不替代新品、断货、门店停业、退单、促销和单位换算的处理。

## 原理参考

- [Forecasting: Principles and Practice 第 3 章的移动平均](https://otexts.com/fpp3/decomposition.html#moving-averages)：移动平均作为平滑工具；居中平滑需要未来值，不能直接冒充实时预测。
- [FPP3 简单预测方法](https://otexts.com/fpp3/toolbox.html#some-simple-forecasting-methods)：均值、朴素与季节性朴素基线。
- [FPP3 时间序列交叉验证](https://otexts.com/fpp3/toolbox.html#time-series-cross-validation)：随时间推进预测起点，遵守信息可用边界。

本文实现使用固定窗口近期均值，是清楚写定的预测规则；不把 FPP3 的全历史均值基线或居中平滑直接改名当作它。
