# 第六篇：单期多来源供给计划实验

全部为教学模拟。禾味背景为2家门店、8个食材SKU，本包只枚举A店1种食材；B店为调出门店。服装案例为匿名企业1个同款同尺码成衣SKU。未访问真实订单、生产环境或采购接口。

## 运行

只需 Python 3.10+ 标准库，无第三方安装步骤。在任意目录执行：

```sh
python3 /绝对路径/practice/run.py
python3 -m unittest discover -s /绝对路径/practice -p 'test_*.py' -v
```

默认读取脚本旁的 inputs，写入旁边的 outputs；重新运行会覆盖这7个结果文件，不改输入。保留原结果可指定 `--output-dir /另一个新目录`。改数据时请复制整个包或用 `--input-dir` 指向自有JSON目录，必须同时有 hewei.json、apparel.json 和 counterexample.json。

## 这次实验解决什么

在一个已知截止时点，先选固定的采购、调拨和生产量，再在低、中、高三种需求情景下评价。输入中的 demand 是**扣除已核实可用现存和既有及时在途后的剩余净缺口**，包括本次预测范围内的预售留存及新增需求，不再另加同一订单、不再重复扣库存。净缺口的准备过程不在本脚本内，现实中必须单独审计。

模拟时间：1月1日08:00决策，1月2日08:00截止，全部来源默认07:00到齐；到货时刻恰等于截止点算及时，晚一秒即把该来源上界置零。输入 known_at 是整份快照的可知时间，不能晚于决策。真实系统应逐记录追溯，不可仅相信一个快照标签。

所有需求都在该截止点统一结算，本模型不计算期限内分日销售或先后缺货，不建效期、到货随机性、跨期在途或多阶段追单。只假设这些**给定需求情景**随机；可用来源、质量、材料和到货是确定的。本案例成本和概率为事先指定的练习数，不是估计结果，所以不使用180天训练/验证/测试，也不读取其他课程封存数据。不能将本例当预测精度或真实收益评估。

## 公式与成本边界

p、t、w分别是采购、调拨、生产量，q=p+t+w。正文用m表示生产量，对应本代码及结果三元组的第三项w；两者是同一个变量，不是额外来源。来源成本：

`C_source = Σ(unit_cost × source_quantity + fixed_cost × I(source_quantity > 0))`

I表示条件成立为1，否则0。来源成本在每个情景均全额支付，不因最终需求少而退回。情景成本：

`C(q,d) = C_source + shortage_cost × max(d-q,0) + surplus_cost × max(q-d,0)`

总期望为各情景概率乘情景成本再求和。缺货cost是指定的教学罚损，不是声称实际利润；余货cost是**来源成本之外**额外处理/占用费用，不是把进货成本重新计一次。材料采购成本已包含在生产unit_cost内；本包不另计材料成本、不设残值。本定义与上一章只计算净短缺/余货损失的报童示例不应混合相加。

两种目标都最小化同一模型的期望总成本：
- expected：只受来源、批量、材料与容量约束。
- high_service：额外要求q≥所有给定情景中最大净缺口。并非最坏成本最小化。只在这些需求情景和确定供应假设下保供，不代表真实100%服务。

所有金额和概率使用 Fraction 精确分数；输出 `231/2` 表示115.5，不是字符串排序。所有并列最优都保留。selected取(采购量,调拨量,生产量)字典序最小，仅用于确定性复现，不代表业务偏好。若高情景无法满足，返回 INFEASIBLE、空selected、要求数量required_quantity及实际枚举可达上限max_feasible_quantity，并保留来源、材料、批量和接收容量等上界说明。这不是通用的最小冲突集合诊断，不伪造一张保供订单。

## 输入和结果核对

### 禾味（单位kg）
批量5、接收容量50。采购上限40，3元/kg；调拨上限35−15=20，1元/kg和启用30元。生产禁用。净缺口20/30/40，概率0.2/0.5/0.3。缺货10元/kg，余货额外1元/kg。

期望方案(p,t,w)=(10,20,0)，来源成本30+20+30=80元。情景成本90/80/180，期望18+40+54=112元。期望失销3kg、余货2kg；按期望数量汇总的满足比例(31−3)/31=28/31≈90.32%，不是逐情景满足率的简单平均。

高情景保供方案(20,20,0)，来源110元，情景成本130/120/110，期望119元。失销0，期望余货9kg。比前者期望成本高7元是本例服务约束的代价，不是实际费用承诺。

反例由独立输入 counterexample.json 给定确定净缺口10kg，其基准来源条件与禾味主例相同。修改 hewei.json 不会暗中修改反例；如需改变反例，显式修改 counterexample.json。两个固定探测方案若违反修改后的批量或来源上界，会输出 INFEASIBLE，不会中断整个运行。先用最便宜单价调拨10，来源成本10+30=40元；采购10仅30元。单价优先忽略固定费会错选。该反例是另一个明确输入任务，不是看完情景再改变原方案。

### 服装（单位件）
批量10、接收容量100。采购上限80，8元/件；调拨上限70−30=40，3元/件加60元启用费；生产机器上限60，但给定合格面料100米、2米/件，只支持50件，4元/件加40元启用费。面料为本包唯一BOM资源。每件固定毛布消耗为2米，既定损耗已经内含，不另计算损耗或再除以利用率；生产单位成本已经包含材料成本。其余物料假设已齐套，不代表完整BOM核验。

净缺口60/80/100，概率0.2/0.5/0.3。缺货20元/件，余货额外2元/件。期望方案(0,40,50)，来源120+60+200+40=420元。情景成本480/440/620，期望96+220+186=502元。期望缺口3件、余货11件，满足比例79/82≈96.34%。

高情景保供(10,40,50)，来源500元，情景成本580/540/500，期望536元。失销0、余货18件；期望成本增加34元。

枚举禾味42组、服装191组可行来源组合，并列最优在本基准均只有1组。输出候选CSV可逐行审计，结论仅是这个有限模型中的最优。

## 文件

- inputs/*.json：完整输入、时间、来源、成本、净缺口情景。
- outputs/*_candidates.csv：完整可行组合及精确期望结果。
- outputs/*_candidate_scenarios.csv：全部候选逐情景费用，基准禾味126行、服装573行。
- outputs/*_result.json：期望方案与高情景保供方案、全部并列最优、分情景账。
- outputs/greedy_counterexample.json：单价排序反例。
- run.py：验证、枚举、成本评价和输出。
- test_run.py：回归测试，涵盖非法输入、时间、上界、不可行、精确并列、固定方案与复算。

## 练习

1. 把禾味调拨到货改成截止后1秒：它的上界变0，期望最优变为采购30kg，期望122元。
2. 把禾味接收容量改35：期望方案仍可运行，高情景保供应为INFEASIBLE。不能输出35并称满足40。
3. 把服装面料改90米：生产上界45，但整批最多40件。先保留输入版本，再运行比较；不得把修改后的结果混称原基准。
4. 把调拨单位成本和采购单位成本都改成精确0.1、调拨固定费改0，给确定10kg缺口，三组(0,10,0)、(5,5,0)、(10,0,0)应全部列为最优。

运行先完整验证并计算三份输入，再写结果；输入校验失败不会留下半套新结果。但磁盘写入失败不具有事务保证，应使用新的输出目录并核对全部7文件。输入核验不能证明业务数据真实。程序没有联网和自动下单，结果是供人审阅的建议。未建共同供应风险、共享全网能力、替代料、工序路由、质量放行、资金预算和动态履约，不能称企业级MRP/APS或自动运营系统。
