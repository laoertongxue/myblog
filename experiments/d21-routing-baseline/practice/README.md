# D21：最短路与配送基线

本包全部数据为教学模拟，Python 3.10或以上，仅用标准库。不接地图、生产订单或真实派车系统，不使用历史预测测试标签。

## 运行

在本目录执行：

```bash
python3 -m unittest -v
python3 run.py
```

可以在任意目录以脚本绝对路径执行。输入默认取脚本旁的 inputs；`--input-dir` 可指定复制后修改的练习输入，`--output-dir` 可指定新的结果目录。默认运行会重写 outputs 中同名派生结果；请勿在里面存原始文件。固定输入与结果的完整性见 MANIFEST.sha256，修改练习时保留原包，不能把新结果登记成原结果。

## 输入与边界

- `shortest_path.json`：独立四节点无向道路，单位米，null 表示没有直连边。非负边允许使用 Dijkstra；不支持负权。
- `hewei_extension.json`：禾味原背景为2店、8食材SKU、14天首周样本；本10点是独立教学扩展，不是原2店的实绩。每日每点2箱是外生设定，未将食材公斤需求自动转换为箱。
- `apparel.json`：匿名服装企业集货仓向10个虚构协同收货点纯配送已装箱货物。不是跨工序取送货调度，也没有先后依赖、等待或质检状态。

两个10点实例均使用11×11整数米距离矩阵。示意坐标在正交道路网格上，每格1000米，距离为横纵距离之和。矩阵对称、对角线零且满足三角不等式；不代表真实道路、拥堵时间或导航接口。当前验证器按此教学合同拒绝不对称矩阵，现实单行道路可有非对称距离，但必须扩展合同，不能因此说现实数据错误。

每车最多12箱，均只出车一次，不中途回仓补货，不拆单。纯配送的最大载荷在出发时；随着卸货递减。两车按编号固定各服务5点，每车10箱，路线均回仓。容量单位是本实验抽象的同规格箱，未同时约束重量、体积；2箱食材与2箱服装不可跨案例等同货值或重量。

## 手算最短路

A—B为4000米，A—C为1000米，C—B为2000米，B—D为1000米，C—D为5000米，A与D没有直连边。起点A的最短路标签依次确认：A=0，C=1000，B=3000，D=4000。最短路径 A→C→B→D，总长1000+2000+1000=4000米。对照 A→B→D 为5000米，A→C→D 为6000米。这是独立小图，不拿它的节点当10点配送实例。

最短路只决定两点间怎么走；TSP还决定单车访问顺序；VRP还决定多车分配。沿道路经过某收货点不等于完成该点服务。本包没有实现TSP或VRP优化器，不保证基线最优，也没有优化后节省率。

|案例|车辆1路线|车辆2路线|距离合计|发车载荷|
|---|---|---|---:|---|
|禾味教学扩展|0-1-2-3-4-5-0|0-6-7-8-9-10-0|20000米|各10箱/容量12箱|

禾味每条10000米，其中回仓4000米；服装每条14000米，回仓分别3000与4000米。不能把20公里和28公里跨不同网络相减声称节省。未来只可比较相同输入、同一服务要求与约束下的可行方案。

## 输出和验收

- `summary.json`：两案例的逐车路线、完整距离、初始载荷和汇总。
- `route_legs.csv`：24行逐段账，记录发车载荷、交货箱数、抵达卸货后余量；含回仓段。`arrival_remaining_box` 是交货后余量，不是刚到达未卸货时的载荷。
- `shortest_path_result.json`：最短路与确认顺序。

校验点包括矩阵形状、单位、节点范围、对角线、对称、三角不等式，每点恰好服务一次，两车都回仓、无超载。每段载荷满足 `departure_load_box - delivered_box = arrival_remaining_box`；每车最后余量为零。验证器只检查已经编码的约束，没有时间窗、班次、限行、冷链、装卸时间或司机工时。可行仅相对于这个简化模型。

参考：[OR-Tools车辆路径概览](https://developers.google.com/optimization/routing)。本包自写最短路演示与基线验证，无OR-Tools依赖；没有把官方求解器结果冒充本实验结果。

输入校验同时检查坐标每点为两个整数、网格步长为正整数，并逐项验证矩阵等于坐标的曼哈顿距离乘以步长；坐标与矩阵不得各改各的。最短路 JSON 顶层必须为对象，非法类型以退出码 2 报输入错误，不打印调用栈。
