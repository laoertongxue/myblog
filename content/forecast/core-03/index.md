<p>主商品是 SPU <code>TEA</code> 下的 SKU <code>T-L</code>（500 ml

是可独立计数的商品，SPU 是产品家族。这里“一瓶”记作 <code>ea</code>；6
瓶为一箱。原料有糖浆 <code>R-SYRUP</code>、包装膜 <code>R-FILM</code>
和空瓶 <code>R-BOTTLE</code>。</p>
<p>统一决策时点为 2026-06-15 08:00 UTC，主要计划到货日为
06-17。<code>event_date</code> 是业务发生日期；<code>target_date</code>
是记录适用的预测/计划日期；<code>known_at</code>

<p>覆盖
A03。目标是做一次没有“偷看答案”的多源连接，并区分历史重放与新时点重算。</p>
<h3 id="三个时间不能混淆">1 三个时间不能混淆</h3>
<p>06-14的销售126瓶在06-14
23:59可得。纠正后的132瓶也是06-14发生的销售，但到06-15
10:00才可得。08:00做预测时只能用126；11:00新做预测可以用132。</p>
<p>选择规则是先筛
<code>known_at ≤ cutoff</code>，再在同一业务事件里取最新修订版本。对快照则按“系统+字段+target_date”筛选，再取可得时间最新者。来源、目标日期、版本以及
cutoff 都要保留。</p>
<p>|来源|08:00可用|之后才可用|本实验的用途|
|POS|06-14销售126|10:00纠正为132|去星期的WMA|
|OMS|独立渠道已确认30|没有后续修订|预留库存，不混入POS销量|
|WMS|可售180、确定在途60|没有后续修订|库存位置|
|MES|06-17产能90|09:00改为60|工单上界|
|天气|06-17降雨概率0.7|09:00预测改0.2，17日晚才有实际值|保留为特征快照，不擅自给销量加倍|
|竞价/活动价|已公告未来价格9元|09:00改为8元|记录已知外部条件|
|IoT|07:50测得6℃、07:55可得|07:55测得12℃、08:20才可得|风险提示，不自动放行或报废|
|BOM|生产日适用B1|09:00才知道未来B2|按生产日选用量|</p>
<p>外部天气和价格在本包只进入可追溯特征快照，没有估计出它们对销量的效应。能接入一个字段与证明它能改善预测是两件不同的验收。</p>
<h3 id="迟到重算的算术">2 迟到重算的算术</h3>
<p>08:00的最近三天去星期值是120、120、140，权重为1、2、3，加权基准为130。11:00最后一天改为132÷0.9=146.6667，新的基准为：</p>
<p><code>(120×1 + 120×2 + 146.6667×3) ÷ 6 = 133.3333 瓶/日</code>。</p>
<p>未来三天星期系数和为0.9+0.9+1.2=3，所以累计预测从390变400瓶。其他条件相同时，整箱建议从210变222瓶，增加12瓶。修订的6瓶历史销量不一定让建议只增6瓶，权重、预测期限和箱规会改变传导。</p>
<p>旧预测 <code>F08</code> 应保留126及原输入哈希；新预测
<code>F11</code>
才用132。拿F11的结果覆盖F08，会让人误以为08:00已知道10:00才收到的消息。</p>
<h3 id="输入-输出和项目">3 输入 输出和项目</h3>
<p>输入 <code>pos.csv</code> 与 <code>snapshots.csv</code>。使用
<code>asof_events</code>、<code>asof_snapshot</code>。运行后比较
<code>pipeline</code> 与
<code>late_pipeline</code>。11:00示例把收货容量从210设为240，<strong>仅作为容量重新批准后的独立情景</strong>；若仍用210，222应被挡住。主线原有60瓶在途须于06-16开门前可用，不能只看06-17累计量。</p>
<p>练习：把纠正记录的 known_at
从10:00移到07:59。答案：08:00也可用132，基准应变133.3333。把IoT事件复制成同字段同可得时间但不同值，应该报
<code>AMBIGUOUS_SNAPSHOT</code>，而不是随机取最后一行。</p>
<p>故障注入：尝试把06-17实际天气用于06-15预测；本包
<code>kind=actual</code>
不作为天气预测特征。检查cutoff前后的库存快照，不能用事后盘点假装当时已知。源系统若把
known_at 伪造得过早，程序本身无法证明它真可得，仍需接入审计。</p>
<p><strong>边界：</strong>
没有实时CDC、消息队列、时区转换器或真实时钟签名；所有时间是格式一致的UTC字符串。</p>
