</details><h2 id="模块-sg01-从订单展开为年龄hazard的实际拟合">模块 SG01
从订单展开为年龄hazard的实际拟合</h2>
<p>对应P14。目标是得到“这张订单已经等到第a天且尚未取消、尚未发货时，接下来这一天取消的概率”。不是“下单以来总取消概率”，更不是“所有年龄订单一起算一个比例”。</p>
<h3 id="第一步-一单多行与风险集">第一步 一单多行与风险集</h3>
<p>person-day直译为“一个人一天”，这里是一张订单一个等待日。订单A在第3天取消，应写三行：(A,1,0)、(A,2,0)、(A,3,1)。最后一个数字y取0表示当天未取消，取1表示当天取消。第4天不能再写A。订单B在第2天结束时发货，写(B,1,0)、(B,2,0)，之后停止。订单C观察只到第2天，也写两行0，但原因是观察截止，不是已经永不取消。</p>
<p>本项目约定：每天先观察取消，日末发货；同一天两种潜在事件时取消优先。风险集包括该天开始时仍等待的订单。现实事件若只有日粒度且先后不清，必须先制定并做敏感性分析，不能悄悄套本规则。</p>
<p>小例子：某日开始有10张未发货未取消订单，当日取消2张，则当天经验hazard=2÷10=0.2。第二日只有8张还在等，若又取消1张，当天hazard=1÷8=0.125。它不是1÷10。到第二日末仍等待的比例=(1−0.2)×(1−0.125)=0.7，累计取消比例=1−0.7=0.3。</p>
<p>“发货停止继续观察”叫删失。它与取消不是同一个标签。只有当发货选择与潜在取消在已知条件下足够独立，才可把拟合的等待hazard用于假设继续等待的情景。本模拟刻意让发货时机在给定仓库后独立于潜在取消。现实中高价值顾客优先发货，可能还存在未记录的VIP信息；加入价格和仓库不能证明这种偏差已经消失。</p>
<h3 id="第二步-逐个拆开年龄哑变量与logit">第二步
逐个拆开年龄哑变量与logit</h3>
<p>模型写成：</p>
<p>z = b₀ + b₂I(a=2) + b₃I(a=3) + … + b₁₂I(a=12) + β₁x₁ + β₂x₂ +
β₃x₃</p>
<p>h = 1 ÷ (1 + exp(−z))</p>
<ul>
<li>a是等待年龄，单位“天”；本项目只训练第1至12天。</li>
<li>I(a=2)是开关：a等于2就取1，否则取0。其余年龄开关相同。</li>
<li>第1天没有自己的开关，全部年龄开关为0时，b₀就是第1天的基础分数。少放一个开关是为了避免“截距加所有开关”重复表达同一个量。</li>
<li>x₁=price÷100，例如120元写成1.2，不是120；β₁是每100元价格对应的分数变化。</li>
<li>x₂是虚构仓库0/1，x₃是是否促销0/1。0和1在本模拟确实是二分类，不可把仓库编号8误当成仓库编号1的八倍。</li>
<li>b和β是训练找出的数，不是人为写好的概率。z可以正也可以负。</li>
<li>exp(u)表示自然常数e约2.718的u次方。exp(0)=1，所以z=0时h=1÷2=0.5；z越大，h越大，且始终在0到1之间。</li>
</ul>
<p>logit(h)=ln[h÷(1−h)]是上式的反变换。ln是以e为底的对数。h=0.25时，h÷(1−h)=1÷3，ln(1÷3)≈−1.0986。把z=−1.0986放回第二式，得到h≈0.25。本模型叫离散时间logistic
hazard；虽然有年龄基础项和订单特征，仍不能因此叫Cox模型。</p>
<p>手算练习用一组自设系数，不是本次训练成绩：b₀=−2，某一天龄开关项=0.3，β₁=0.2且x₁=1.2，β₂=0.4且仓库=1，促销项=0。先算z=−2+0.3+0.2×1.2+0.4=−1.06；再算h=1÷(1+exp(1.06))≈0.2573。不能把四项概率直接相加。</p>
<h3 id="第三步-拟合到底在做什么">第三步 拟合到底在做什么</h3>
<p>每行真实答案y只有0或1，模型给h。若实际取消y=1，给它0.8比给0.1更合理；若未取消y=0，给0.1比给0.8更合理。对数损失逐行写为：</p>
<p>loss = −[y×ln(h) + (1−y)×ln(1−h)]。</p>
<p>y=1、h=0.8时，loss=−ln(0.8)≈0.2231；y=1、h=0.1时，loss≈2.3026。小才好。程序反复调整系数，让训练行平均损失加系数惩罚更小。C越小表示惩罚越强，不表示概率越小。验证集在C=0.1、1、10中选一个，测试集只打一次分。</p>
<p>程序先标准化数值再训练：标准分=(原数−训练均值)÷训练标准差。只能用训练均值和标准差，不能先用全数据计算。outputs/hazard_coefficients.csv已把系数还原到原始特征单位，读者可以直接按“价格÷100、仓库0/1、促销0/1、年龄开关”复算，不必再重复标准化。</p>
<p>Brier分数是平均(h−y)²。一个取消样本的h=0.8，误差平方=(0.8−1)²=0.04；一个未取消样本的h=0.8，误差平方=0.64。所有行平均越小越好。这里它评估的是“被观察到的风险日”，不是证明未发货反事实曲线正确。</p>
<h3 id="第四步-真实项目输入与验收">第四步 真实项目输入与验收</h3>
<p>输入hazard_orders.csv有id、day、price、warehouse、promo；hazard_events.csv有订单id、事件日和cancel/ship。程序只从订单特征和已发生事件构造person-day，不从潜在真值建特征。</p>
<p>训练订单日0至99，观察到112；验证订单日120至159，观察到172；测试订单日180至219，观察到232。中间留间隔，保证12天标签已经走完。训练、验证、测试分别是2000、800、800张订单；person-day数分别为11777、4702、4852。原始表另有未用于这三个块的订单，不可把4800都称训练样本。</p>
<p>检查四件事：每单最多一行y=1；取消后没有行；各块id不交叉；known_at不晚于当天开始。默认结果选择C=1，测试Brier约0.07366；只用年龄的基线约0.07439，改善很小，不能用“显著领先”描述。hazard_age_calibration.csv把年龄逐行的平均预测与实际取消比例并列。</p>
<h3 id="第五步-条件留存与边界练习">第五步 条件留存与边界练习</h3>
<p>设S(a)是在约定继续等待且不发货、相应删失条件成立的情景中，到第a天仍未取消的留存概率。它不是现实中同时受到发货退出影响的“还在等待订单占原始订单的比例”。已知订单已经活到a天，再等L天的留存概率是S(a+L)÷S(a)，也等于从第a+1到a+L天的(1−hazard)相乘。历史已经取消的订单不能再扣第二遍。</p>
<p>例如前面第一天留存0.8，后两天hazard为0.1、0.25，则S(3)=0.8×0.9×0.75=0.54。对当前已经过第一天的80单，用0.54÷0.8=0.675，预计剩54单。错用80×0.54只得到43.2，是重复扣了第一天的取消。</p>
<p>练习：把某个事件改到订单创建前，再运行--reuse-inputs，应明确失败；把价格提高100元，复算z变化是否恰为β₁。第13天及以后没有支持，函数拒绝超范围，不能把第12天hazard无限外推。本补课不推断消费者因果耐心，不证明删失独立，不把同一订单的多行当独立样本计算显著性。</p>
