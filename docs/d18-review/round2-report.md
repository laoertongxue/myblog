## 已闭环 P2：任意精度公式输入可在向上取整前丢失正尾数

原始发现位置：修复前 `experiments/d18-safety-stock/practice/run.py:48–83`，尤其第 70–75 行。以下保留发现与复现记录，不代表最终实现仍存在此问题。

`target()` 接受未限制有效位数和指数的有限 Decimal/字符串均值、标准差及 z，但在固定 40 位上下文中形成 `raw`，再执行 `ROUND_CEILING`。整数阈值上方的很小正尾数会先被舍去，最终目标少一个取整步长。

修复前独立复现：

```python
from run import target
# 第一个 mean 是 1 + 1e-41。
target('1.00000000000000000000000000000000000000001', 0, 1, 0, 'kg', 1)['target_level']
# 实际 '1'，按精确输入向上取整应为 2。
target(6, 2, 4, '1e-50', 'kg', 1)['target_level']
# 实际 '24'，24 + 4e-50 向上取整应为 25。
```

影响：只影响通用函数的超高精度/极小正值边界；固定候选 z=0、1、1.645 和本篇九条训练数据不触发。README 已说明统计使用 40 位近似，且本文不是生产系统，因此不将其升级为当前内容的发布阻断项。

当时建议修复：对均值/标准差/z 明确并校验支持的有效位数及最小非零值，或者使用足够的受控保护精度和可证明的取整边界处理；无法可靠决策时拒绝，而不是静默给出精确取整外观。加入上述两个回归用例；不要仅把 40 改成另一个固定数而继续接受无限精度。保留“公式统计近似、日账精确”的区分。

### 修复后独立复验与闭环

- 最小非零moment=1e-6、最小非零z=0.001、零需求矩、S上界1,000,000、0.003等不整除上限的步长、整数及非整数平方根均正确；调用方极低精度和强陷阱不改变结果。
