## 发现

### R1-01 中等：最短路输入顶层结构未验证

位置：practice/run.py 的 run()，`graph.get('distance_unit')`。

复现：复制 inputs 至临时目录，把 shortest_path.json 内容设为 `[]`，执行 run.py --input-dir 临时目录 --output-dir 另一目录。程序退出1，抛 `AttributeError: 'list' object has no attribute 'get'` 栈，而不是既有 `输入或文件错误` 提示与退出2。`null`/整数同类输入也会出错。

建议：访问 get 前检查 dict；明确 matrix/start/target 必填；补顶层 list/null/string 等 CLI 边界测试。不能仅吞掉所有异常，避免把程序缺陷误作输入错误。

### R1-02 中等：坐标来源与成本矩阵可自相矛盾而验证仍通过

位置：validate_case() 未检查 coordinates_grid/grid_step_m 与 distance_matrix 的关联。

复现：保持禾味矩阵原样，只将 `coordinates_grid[1]=[999,999]`，validate_case() 返回通过。`grid_step_m` 被改也不会被发现。文章、输入和README声明每格1000米及横纵距离构造矩阵，因此这是可复现输入的来源契约，不只是美观元数据。读者修改坐标练习后可能误以为已经更改实验地理位置，实际运行仍用旧矩阵。

建议：本固定教学合同下检查坐标数量、每项两整数、grid_step_m正整数，以及全部矩阵值等于横纵差绝对值之和乘步长。或者明确把坐标移至非计算示意，声明矩阵唯一权威且修改坐标不影响计算；前者更适合现有叙述。补错长度、bool/float、步长及坐标-矩阵不一致测试。
