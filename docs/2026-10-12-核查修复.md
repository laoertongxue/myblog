# 代码核查与修复（2026-10-12）

对全仓库做了一次通读核查，按影响面修掉 6 类问题。每个结论都有可复现证据，所有改动以
`make check`（含真实浏览器检查）全绿为准。

## P1 线上 HTML 泄漏 Go 模板占位符 `zgotmplz`

- **现象**：线上 `https://12lab.cn/` 首页有 16 处、整站构建产物 1208 处
  `<a href=/search/ zgotmplz>`；`aria-current` 属性被整个顶掉。
- **根因**：`layouts/_partials/lab/site-header.html` 把
  `{{ with partial "lab/nav-current.html" (dict "page" $ "menu" .) }}aria-current="{{ . }}"{{ end }}`
  写在 `<a href="…"` 之后的**属性名位置**。Go 的 `html/template` 在 partial 返回空串
  （即"非当前栏目"，绝大多数导航链接）时会输出字面量 `ZgotmplZ`。
- **修复**：5 处导航链接一律先把 partial 结果存进变量，再 `{{ with $current }} aria-current="{{ . }}"{{ end }}`。
  最小复现已记录在 `AGENTS.md`（"属性名位置不能直接写 `{{ with partial ... }}`"）。
- **防回归**：`scripts/check.sh` 的 grep 家族新增 `zgotmplz` 断言。已验证正反两面：
  修复后 0 处；把其中一处改回旧写法后构建出现 320 处并被断言拦住。

## P2 六个浏览器检查从未被自动执行

- **现象**：`scripts/check-design-browser.js` 等六个文件都是
  `async (page) => {}` 闭包（供 Playwright `run-code` 粘贴执行），不是程序——
  `node scripts/check-design-browser.js` 静默退出 0；全部硬编码 `127.0.0.1:1316`，
  而仓库里没有任何东西启动该服务；无依赖清单；`check-adversarial-ui.js`、
  `check-agent-series-browser.js`、`check-thumbnail-fit-browser.js` 全仓库零引用。
- **修复**：
  - 新增 `package.json` + `package-lock.json`（唯一 devDependency：`playwright`）与
    `scripts/run-browser-checks.mjs`：自带静态服务（1316，行为对齐 Caddy，含真实 404）、
    每个检查独立浏览器上下文、统一挂 `pageerror` / `requestfailed` / CSP 违规监听、
    单个检查看门狗与聚合失败退出码。
  - `scripts/check.sh` 接入：`auto`（默认，缺 playwright 打印 `skip` 而不是静默）、
    `BROWSER_CHECKS=require`（CI 用，缺依赖即失败）、`BROWSER_CHECKS=0`（临时跳过）。
  - `deploy.yml` 构建前 `npm ci` + `npx playwright install --with-deps chromium --only-shell`，
    并以 `BROWSER_CHECKS=require OUT=public make check` 运行。
  - `ctx` 提供 `base`/`assert`/`pagerSize`（读 `hugo.toml`）/`walkPagination`/`rssCount`，
    并把 **Caddyfile 里的 CSP 施加到本地服务**上（见 P6）。
- **顺带修掉的断言缺陷**：`.site-sidebar/.list-aside`（仓库里 0 次出现，永不可能失败）改为
  "workspace 只有 `main`+`footer`、主列占满 99%"；`.home-intro` 若不存在则恒真 → 改为
  "feed 非空、每页不超过 pagerSize、与 header 间距 ≤40px"；`if (await images.count())`
  包住整段断言 → 改为按 listing 推导"有预览就必须恰好一个高优先级"；写死的
  `rgb(250,248,241)`、`10 篇`、`11 张图`、`1697×927`、`2 个章节` 等改为从
  `--lab-paper`、`hugo.toml`、内容与源图文件头推导；TOC 断言补上"链接目标必须存在"
  （原来只等 hash 变化，锚点坏掉也会通过）。

## P5 专题检查与内容强耦合

`scripts/check-agent-series.py` 原来写死章节路由、标题、11 个图片文件名、原始像素
（1697×927 等）、10 段目录、2 张表、5 个引用锚点与"全站只有一个专题"，任何合理的内容改动
都会误报。现在全部改为推导：

- 章节、顺序、标题 ← front matter（`weight`/`title`）；正文图片与顺序 ← Markdown 的图片引用；
  列表预览 ← front matter `images`（缺省时按 bundle 名序），上限 3 张 ← `thumbnails.html`；
  默认方形裁切尺寸 ← `thumbnails.html` 的 `.Fill` 字面量；
- 每张图的预期渲染尺寸 ← 源图文件头（PNG/JPEG/WebP/SVG 尺寸解析，无第三方库）+
  `layouts/_markup/render-image.html` 的 1440 上限规则；`srcset` 候选集合与每个候选的实际
  尺寸都去读产物，因此"被裁切/被拉伸"必然被发现；
- 目录条目数 ← 正文 h2/h3 数，且每条 TOC 链接必须在页面里存在对应 id（主题把 id 放在
  标题锚点 span 上，所以不能假设在 h2 上）；表格数 ← 源 Markdown 的分隔行；`ref-N` ← 页面里
  实际存在的 id 与链接双向核对；bundle 里既未渲染也未声明为预览的图片会报错（捕捉误删正文图）。

反实验证明它仍然能拦：删标题 / 把 `Resize` 改成 `Fill` 裁切 / 删正文图（声明了预览的章节）/
改坏 `ref-5` 锚点 4 种回归全部 FAIL；新增第三章、把某张图换成不同尺寸重新导出，仍然 PASS。

## P6 服务器侧

- `scripts/Caddyfile`：新增 HSTS（`max-age=15552000`，不带 `includeSubDomains`/`preload`）与
  CSP（`default-src 'self'`、`script-src 'self'`、`style-src 'self' 'unsafe-inline'` 以支持

  仍按既有约定需管理员执行 `scripts/server-init.sh` 才生效。
- CSP 的可验证性：`scripts/run-browser-checks.mjs` 从 Caddyfile 读出 CSP 并施加到本地服务，
  浏览器检查同时监听 `requestfailed`（CSP 拦截表现为 `... csp`）与控制台 CSP 报错。
  已验证：把 `script-src` 改成 `'none'` 会让检查失败；真实策略下行内 `application/ld+json`
  数据块正常解析、无任何控制台报错、设计令牌与图片均正常。
- 主题可追溯：新增 `themes/hextra/12LAB-VENDOR.md` 记录上游、版本、vendor 提交、许可与升级方式
