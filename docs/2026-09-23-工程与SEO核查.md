# 工程、性能与 SEO 核查（2026-09-23）

范围：Hugo 模板、构建/发布脚本、图片、浏览器交互、索引与订阅输出。基线为 `7986155`，使用同一 Hugo 0.166.0 生产构建比较；不改既定的单栏设计、移动端导航、文章目录及每页 10 篇的交互。

## 已修复

| 问题 | 处理 |
| --- | --- |
| 分页第二页 canonical 和 og:url 指向首页 | head 与正文共用分页数据源，分页使用独立 canonical、分享地址及含页码的标题 |
| 测试文章同时输出 index 与 noindex | 自有 head 统一输出一条 robots；测试内容、显式 noindex、搜索及 404 不索引 |
| 测试文章进入 sitemap/RSS | 统一索引规则；纯测试标签不索引；测试内容继续保留给用户验证布局 |
| 分享图指向 assets 中未发布的原图，访问 404 | 分享图通过 Hugo 图片管线输出实际文件；补齐尺寸、alt、Twitter 信息与 Article image |
| robots.txt 没有 sitemap 地址 | 添加完整 sitemap URL |
| RSS 标题重复，夹带测试内容和主题生成的正文锚点 | 自有 list.rss.xml；最新 30 篇可索引文章，输出摘要和正式文章链接 |
| 所有页面下载搜索逻辑 | 通用交互与搜索脚本分离，搜索页专用；索引仅在输入查询后请求，并带内容指纹 |
| 首图 lazy，移动端下载固定大图 | 首张优先、后续懒加载；列表 320/520/1040，正文 480/960/1440 WebP 响应式候选 |
| SVG 正文图缺少占位尺寸 | 从 viewBox 提取比例，输出 width/height，减少布局跳动 |
| 标签/分类页仍使用主题侧栏模板 | 使用与整站一致的单栏，标签文章支持真实分页；解决重复 main 元素 |
| CI 使用已弃用 Node 20 的 actions、runner 随 latest 漂移 | 核对官方 release 后固定 Node 24 的稳定版本、Ubuntu 24.04 和 contents: read 权限；由真实发布验证 |
| CI 只构建，未执行完整回归 | CI 使用 OUT=public make check，通过后的同一份产物上传，保留上传文件数相等门槛 |
| 测试写死 39 篇、4 页及测试文章最小数量 | 浏览器按实际页数校验唯一性；静态检查逐篇校验现存测试文章；独立 43 篇夹具验证五页、草稿与未来日期 |
| 未版本化图片也使用一年 immutable 缓存 | 仅带内容指纹的资源长期缓存；其他资源 no-cache，允许协商验证；服务器配置须单独应用 |
| 服务器初始化脚本会把默认页复制到已部署版本 | 仅首次创建时复制默认页；Caddy 校验、备份、重载、健康检查，失败恢复配置 |
| 默认 404 样式脱离站点且无索引控制 | 同站点布局、返回首页/搜索入口、noindex；Caddy 保持真实 404 状态 |

移动端追加调整：移除首页重复的名称、简介和头像区域，删除该区域的移动端字号/尺寸样式，上方留白缩至 36px；桌面介绍区仍有用途，因此保留共用模板。隐藏头像采用 lazy 避免移动端下载，已纳入浏览器资源检查。

## 检查方法

- `make check`：生产构建、slug/日期、资源及内部链接、43 篇独立分页夹具、新的 SEO 输出断言。旧构建已被新 SEO 检查拒绝。
- `scripts/check-seo.py <产物目录>`：逐页验证 canonical 自指、robots 唯一、描述非空、分享图存在、Article 日期与 image、sitemap/RSS 排除 noindex、robots sitemap 声明。
- 生产产物在端口 1316 预览，通过 Playwright CLI 的 `run-code` 执行以下脚本：
  - `scripts/check-design-browser.js`：18 个路由 × 5 个屏宽，图片、溢出、布局、分页、搜索、目录、无 JS 分页。
  - `scripts/check-mobile-navigation.js`：320/390/760 菜单开关、遮罩、ESC、焦点、尺寸切换、页脚和目录。
  - `scripts/check-resource-loading.js`：390px / DPR 1 实际图片候选、图片优先级/尺寸、普通页不加载搜索、搜索索引按需请求。
- 服务器 Caddy 配置需要校验并单独应用，不能仅以 GitHub Actions 成功推断它已生效。发布后核对 HTTP 状态、实际 meta、分享图、RSS/sitemap、缓存响应头与 404。

## 保留边界

- 36 篇测试文章按用户要求保留。它们可在站内浏览和搜索，但不进入 sitemap/RSS，详情页 noindex。真实写作不应添加 `testContent: true`。
- 未接入 Search Console 或站长平台，不把模板正确等同于搜索引擎已经收录，也不承诺排名。
- 未获取真实访客 LCP/INP/CLS 数据；上面的提升仅限实际测得的资源体积和加载行为。
- 缓存策略调整不能追回用户浏览器之前已缓存一年且尚未过期的同名旧资源；重要的旧图片更新仍应改文件名。

## 依据

- [Google：分页与增量加载](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)：每个分页使用自身 canonical。
- [Google：构建 sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)：提供希望搜索引擎收录的正式 URL。
- [web.dev：优化 LCP](https://web.dev/articles/optimize-lcp)：首屏关键图及时发现、避免延迟加载。
- [Caddy：错误处理](https://caddyserver.com/docs/caddyfile/directives/handle_errors)：通过错误路由输出自定义页面并保持原错误状态。
