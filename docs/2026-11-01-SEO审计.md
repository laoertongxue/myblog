## 专项核查结果

### HTTP、抓取、索引和重复 URL

正式站基线全部 75 个 HTML 请求均返回 200，其中 27 个为预期 meta-refresh 页；任意不存在地址返回真实 404，404 模板带 noindex。`/404.html` 本身作为静态文件可能为 200，不能据此推断随机地址是软 404。

`http://12lab.cn/` → `https://12lab.cn/` 和 `/blog` → `/blog/` 均为 308。`/index.html` 为 200，但 canonical 指 `/`；首页无关查询参数也 canonical 到 `/`。这些变体已有清晰规范信号，暂不增加服务器级重定向。历史 URL 与全部 27 个别名保留，检查其目标存在且无 alias 环或多级 alias 链。

`/page/2/` 原本就正确自引用，保留独立可抓取链接和第 2 页标题；不将分页 canonical 指向首页。当前 sitemap 从 45 变为 44，唯一移除的是尚无文章的 Weekly。首页第 2 页仍由 HTML 分页发现，原本也不在 sitemap 中。搜索、404、空 Weekly 共 3 个实际页面 noindex；其他 45 个实际页面可索引，包括首页分页。页面 HTML 与 X-Robots-Tag 无冲突（本次基线未发现 X-Robots-Tag）。

robots 仍是 Allow:/，允许 Google 读取 noindex 页面、样式、脚本和图片，未用 robots 屏蔽搜索页从而阻止读取 noindex。纯测试内容在隔离 fixture 里验证，未新增到真实 content。

### 内容、作者、图片与性能

11 篇文章均有独立手写描述、发布日期、可解析 Article JSON-LD 和可访问的文章图；保留现有事实与测试声明。作者关于页已有供应链、产品与 AI 学习说明及公开 GitHub 联系链接；没有新增资历、评分、FAQ 或不真实的经历。已有匿名服装企业、禾味虚构品牌和模拟数据说明均保留。

所有封面源均为 900×383，列表每篇一张；正文图按各自比例显示。浏览器完整检查覆盖 68 张独立原图、9 篇博客的 51 张正文图及两篇专题的图示；D7、D8、Super-agent 的 `monochromeImages: true` 和 lossless WebP 路径保留，由现有像素级中性 RGB 断言复核。社交图沿用既有 JPEG/PNG 管线，未把社交预览规格冒充正文图规格。

现有首图 eager/high、后续 lazy、宽高预留、srcset 与指纹化资源没有退化。搜索脚本仅搜索页加载，索引按需获取。未增加外部字体、第三方脚本、分析器或运行时依赖。桌面 1440px、手机 390px/320px 未见横向页面溢出；表格自身允许横向滚动，上一页左、下一页右保持。

独立本地浏览器采样中首页首屏资源传输约 157KB（桌面）/121KB（手机），D8 约 65KB/53KB；本地 LCP 约 80–116ms、CLS=0。这里只是一次无节流 localhost 合成采样，图片懒加载、浏览器缓存及采样窗口都会影响数值；**不是公网性能承诺，不是完整页面资源总量，也不是 CrUX/真实用户 CWV**。INP 需要真实交互分布，不能从本次值推断。

22 个外部链接中 20 个在直接抓取时 200；Creative Commons 和 Infor 在本机 Python TLS 路径报 EOF，但经独立网页获取均能读取正确内容，故不误删为死链。`www.12lab.cn` 的 TLS/上游连接在多种探测路径未成功，本次无法确认具体 DNS、证书或网络原因；主域名正常，不因此修改 DNS、Caddy 域名或安全设置。

## 两轮审查、复验与自动门禁

第一轮从源码和 Google 官方细则审查 head、分页、索引策略、导航、结构化数据与资源链；独立使用正式 HTTP 快照、生产构建解析和从首页的链接图复验，发现并修复分类孤立组与元数据问题。修复后跑完整同源门禁和六组浏览器检查。

第二轮从产物反向检查 index/noindex 范围、sitemap 集合、canonical、所有 fragment、作者和日期；再依据 Git diff 核实历史修改日期，用新的坏产物故障注入确认误 noindex、跨域 canonical、robots 全禁、断 fragment、sitemap 漏页、隐藏作者会失败。另用独立 Chromium 脚本进行 27 个桌面/手机页面组合检查及无 JS 的分类发现路径验证。随后对包含 lastmod 补录的最终候选版本重新执行完整门禁。

本机没有 `make` 命令，因此通过 Git Bash 执行 Makefile 中 `check` 的原样入口 `bash scripts/check.sh`，设 `BROWSER_CHECKS=require`，没有跳过浏览器。Hugo 为与 CI 一致的 `0.166.0+extended`，原生 Windows 运行；下载工具放在仓库外 `E:/12Lab/seo-tools/`，没有使用 Docker。

- 内容、路由、日期、占位符、SEO、图片资源、首页与专题分页 fixture、作者流程检查均通过。
- SEO 的 6 种故障注入均被正确拒绝。
- 发布故障测试报告 `Ran 11 tests`、`OK (skipped=5)`：Windows 实际执行 6 项，5 个相对 symlink 切换/回滚用例按平台跳过；**不能写成 Windows 执行了 11 项**。生产发布前 Linux CI 需真实执行全部 11 项。

## 上线风险与后续验证

本次模板会改变全站标题后缀、taxonomy 描述及 Article 作者/更新数据，Google 后续可能重写标题摘要；不能保证每次搜索使用所提供文本。空 Weekly 会退出可索引集合，这是有意选择，首篇正式文章发布后 fixture 保证恢复。类别入口不改变既有主导航菜单或网站布局。没有 Caddy/DNS/安全头配置改动，无需管理员下发服务器配置。

发布流程：确认远端 main 没有新增他人提交 → 提交本次文件 → 推送 main → 核实精确 SHA 的 Actions 构建与部署 → 复抓全部 HTML、robots/sitemap/404 与关键资源 → 校验线上对比候选产物 → 公网 Chromium 桌面/手机 QA。只有构建与发布均成功才能称为完成，不以本地 `public/` 代替线上验证。

需要站点所有者已有 Search Console 权限后再做：检查索引覆盖与 Google 所选 canonical、提交/核验 sitemap、对首页与代表文章运行 URL 检查及必要的重抓取、运行富媒体搜索结果测试、观察后续几周的展现与点击；结合 CrUX/CWV 报告看真实用户分布。当前未进行账号登录、所有权验证、DNS 改动、凭据添加或对外推广，也未创建长期自动化。公开检查无法证明所有页面已收录，实验室结果无法保证排名。
