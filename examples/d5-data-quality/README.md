# D5：把数据异常与业务表现分开

这是完全模拟、可离线复算的教学切片。所有订单号、事件号、数量、时间和实验结果均为模拟，
不含真实企业数据。服装企业匿名；“禾味”是虚构品牌。这里只演示有限规则，不是生产数据清洗工具。

## 安全运行

需要 Python 3.9+（含标准库 `sqlite3`），无第三方依赖、联网、凭据或付费 API。
程序固定使用新建的 SQLite `:memory:` 数据库，不接受数据库地址，不打开任何数据库文件。
所有输入 CSV、SQL 与 `expected/report.json` 只读；实际结果与预期结果分开保存。

```bash
python3 run.py
```

默认在当前目录创建全新的 `d5-results-随机字符/`。也可指定一个**尚不存在**的输出目录：

```bash
python3 run.py --output ./my-d5-results
```

已存在的目录会被拒绝，不覆盖任何原始数据、预期结果或旧实验结果。再次运行请换一个新目录。
22 条断言全部通过后才写结果；其中包括本次期望结果比对与输入哈希不变检查。
如果拿到修改过的教学输入，程序可能因期望不符退出；不要为了“通过”直接更新预期。
所有文本、CSV、SQL、JSON 均显式按 UTF-8 读写；已实际在关闭 Python UTF-8 模式的 C locale 下运行。

## 文件与数据范围

- `data/fashion-original-*.csv`：保留的服装原始教学版（4 条订单行、4 条验收事件）。
- `data/fashion-anomaly-*.csv`：注入问题后的副本（5 条物理订单行、5 条验收事件）。
- `data/candidate-orders.csv`：注入前冻结的 4 单候选清单。
- `data/hewei-original-snapshots.csv`：两天切片的 32 条原始观测。
- `data/hewei-anomaly-snapshots.csv`：注入后剩 16 条，包含 1 个 `NULL`。
- `data/expected-slots.csv`：注入前冻结的 32 个应观察组合。
- `data/hewei-skus.csv`：8 个食材 SKU、各自单位，不跨单位汇总库存数量。
- `schema.sql`、`analysis.sql`：内存库建表与实际分析视图。
- `article-fashion.sql`、`article-inventory.sql`：博文中两段查询的可执行原文件。
- `manifest.json`：时间、范围及本教学样本采集完整性前提。
- `expected/report.json`：事先核算的期望结果；`run.py` 产生实际结果并比对。

服装候选单均为 `TEE-M`，单位为件，承诺时刻原本均为 2026-10-21 12:00（UTC+07:00），
统计时刻为当日 18:00。每单在本切片中只有一个订单行；真实多行订单的异常按整单隔离，
程序另有“异常订单新增正常行也不得漏入”的边界断言。及时验收边界为 `accepted_at <= promise_at`，
恰好截止时刻收货也计入。本例保留完整的模拟验收事件集合，才可将 L3 没有验收解释为计入量 0；
实际接口漏传时，这个前提不成立，应先对账，而不是照搬补零。

禾味背景框架是 2 家门店（S01 江城店、S02 大学城店）、8 个食材 SKU、2026-10-01 至 10-14。
**实际只生成 10-10 与 10-11 两天、每天 18:00（UTC+08:00）的 32 格切片；没有生成完整 14 天数据。**
8 个 SKU 为鸡腿肉、大米、土豆、番茄、生菜、食用油、牛奶、鸡蛋。
原始版中，10-10 的 S01/K01 与 S02/K08 库存为 0；其余 30 格值为各 SKU 自身单位的 10。
这些量值不能混成一个库存总量。

## 六类检查与处理范围

| 检查 | 注入或合法对照 | 本次决策与作用范围 |
|---|---|---|
| 订单行重复上报 | AF01、AF05 共有 FE1 事件身份，全部业务字段相同；物理命中 2 行，多余 1 行 | 确认回放后保留 AF01 作为计算代表，保留两条原始记录和处理日志。不同事件同订单行、或同事件载荷冲突，不自动任选一行。 |
| 孤儿验收 | AR05 的行键 X404 没有对应订单行，数量 40 件 | 保留待归属，阻断当前服装 SKU/日期范围的正式 KPI。不能证明它不影响已关联订单；子集结果只用于诊断。 |
| 负订货量 | AF04（A4/L4）从原始 100 改为 -100 | 阻断 A4 整单及对应正式汇总；不把负数删掉后称完整数据。 |
| 承诺时间缺失 | AF03（A3/L3）承诺时间置空 | 无法可靠判断到期或及时性，A3 整单待确认；不得自行补当天时间。 |
| 快照缺一天 | 副本删除切片中 10-11 的全部 16 条观测 | 仍保留 16 个应观察键，标记 `MISSING_ROW`；阻断完整切片缺货率点估计，但可披露有覆盖说明的已观测值。 |
| 零与 NULL 库存 | 保留 2 条合法零库存；10-10 的 S01/K02 从 10 改为 NULL | 零是有效观测，保留；NULL 是已到达但值未知，标记 `NULL_VALUE`，待确认并从已观测率分母排除，不能补 0。 |

这里的“阻断”是阻断受影响订单或范围的**正式指标发布**，不是删除原始记录、停掉所有订单业务，
也不是禁止展示诊断明细。若归属影响范围不能定位，不能擅自收窄阻断范围。
当前服装完整 KPI 为 `BLOCKED`；禾味只有 15/32 的有效覆盖，完整切片点估计不可得。

同事件出现冲突载荷时，程序从异常版原始行查出所有涉及的订单并整单阻断，
同单其他正常行也不进入诊断。审计使用 `EVENT_PAYLOAD_CONFLICT`，不把冲突行标成确认回放；
只有没有冲突、事件身份与完整业务载荷一致的额外行才计入确认回放数。处理日志按实际查询生成。

库存计算前还有身份门槛：应观察表、原始快照与异常快照的日期／门店／SKU 必须非空且组合键唯一；
快照 `source_row_id` 必须非空（也不接受空字符串）且唯一。门槛在载入后和报告计算前检查，
发现问题会在计算前拒绝并报告表名与命中键／身份，不自动取第一条快照。
正文库存 SQL 的左连接以这个前提为基础；单独使用查询时也必须先执行同样的门槛。

## 可复算结果

### 服装：候选变了，比例就可能变好

原始版：L1 计划 100、分批及时验收 60+40；L2 计划 100、及时收 80；
L3 计划 100、及时收 0；L4 计划 100、及时收 100。
因此原始教学真值为 `(100+80+0+100)/(100+100+100+100)=280/400=70%`。
两个 L1 验收事件是合法分批，不能因为同一行键就折叠成一次收货。

六类问题同时注入并按上述规则隔离后，可关联且可评价的诊断子集为 A1、A2：
`180/200=90%`，候选单可评价覆盖率为 `2/4=50%`，**完整正式 KPI 仍阻断**。
原始版也只取同一 A1、A2，仍是 `180/200=90%`，没有任何业务改善。

另做一个**独立受控实验**：只从原始版屏蔽低表现 A3，其他数据不动，
得到 `280/300≈93.33%`。分子仍是 280，分母少了 100，比例提高只是选择人群改变。
它不是六类同时注入后的最终 90%，两者不能混成同一个处理过程。
原始 70% 是保留教学真值；现实中仅靠承诺时间已丢失的副本，无法自己恢复原始到期人群。
`2/4` 的分母是注入前冻结候选清单，不代表已经证明了生产全量应到期订单覆盖率。

### 禾味：零、NULL、无记录各有自己的位置

原始 32 格：零 2、正 30，零库存观测比例 `2/32=6.25%`。
异常版：32 个应观察键，收到 16 条；其中正 13、零 2、NULL 1，另 16 格无记录。
有效观测为 15，覆盖率 `15/32=46.875%`，已观测零库存比例 `2/15≈13.33%`。
这不是完整两天切片的真实缺货率，也不能由此认定履约变差。

17 格（1 NULL + 16 无记录）的状态未知。仅就“库存是否等于 0”这个状态问题，
完整 32 格的可能比例在 `2/32=6.25%` 至 `(2+17)/32=59.375%` 之间；
这是按未知状态作两端假设的可能范围，不是统计置信区间，也不是一个真实点估计。
如果把 NULL 与缺记录全补 0，就会得到 `19/32=59.375%`，恰好把最坏端点冒充已知事实。
零库存观测也不自动等于全天缺货时长、未满足需求量或服务表现，仍需对应业务证据。

## 实际结果与追溯

每次运行生成：

- `report.json`：上述计数、分子、分母、覆盖率、诊断值、发布状态与上下界。
- `inventory-audit.csv`：全部 32 个应观察组合的逐格状态；不存在的记录不伪造 source ID。
  `teaching_original_*` 列只用于核对保留教学版，不代表现实中可以恢复未知值。
- `fashion-line-audit.csv`：5 条物理订单行与原始来源、处置状态。
- `diagnostic-lines.csv`：A1、A2 的行级计划、及时验收与封顶计入量。
- `issue-log.csv`：命中键、原始来源行、数量、处置与作用范围；零库存列为保留的有效观测。
- `checks.json`：已通过断言名称及输入 SHA-256，确认运行未修改原始或异常 CSV。

自检还覆盖：相同事件冲突不任选载荷、冲突不算确认回放、冲突审计分类、同单正常兄弟行阻断、
不同事件同业务键不自动去重、快照组合键重复、来源 ID 缺失／重复、空应观察键和空分母返回 NULL。
新增业务场景要先补数据契约和相应断言；不要把这组小切片当成企业通用质量规则或完整历史审计。
