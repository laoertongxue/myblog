# D6：三项 SQL 指标与边界测试

全部数据为教学模拟。匿名服装企业的业务背景只用于说明生产交付协同，没有真实企业名称、单号或经营收益。禾味是虚构企业。本包不连接生产，不执行采购、派车或发布。

## 一分钟运行

需要 Python 3.10+，仅用标准库，无须安装第三方依赖。在本目录执行：

```sh
python3 tests.py
python3 run.py --out output-local
```

预期测试输出：`PASS: 202 assertions ...`。第二条命令输出 CSV 和 `audit.json`。结果目录已存在时，程序拒绝覆盖；请改用新的 `--out` 路径。CSV 为 UTF-8，比例输出为 0–1 小数，空单元格代表 NULL／不适用，不是 0%。

`expected/` 是程序生成的一次基准结果，不是独立手算答案。独立手算断言明确写在 `tests.py`；该文件还有不执行 SQL 的逐事件参考算法。不要把 `expected/` 作为新输出目录。`data/` 已提供六张输入 CSV，运行不需要重新生成。若主动要重建原始模拟数据，执行 `python3 build_data.py`；此命令明确覆盖 `data/` 六表，但不改结果目录。

`metrics.sql` 定义中间视图及三个结果视图。`run.py` 先校验输入、装载六表与参数、生成预期快照网格，再执行该 SQL。它不是可以脱离输入表直接在任意数据库运行的一段 SQL。

## 观察口径和简化假设

- 时区统一为 Asia/Shanghai。本包保存无偏移的本地时间字符串，格式严格为 ASCII 数字的 `YYYY-MM-DD HH:MM:SS`；不接受混合时区、不同格式或非法日期。
- 观察期 `[2026-10-16 00:00:00, 2026-10-30 00:00:00)`，统计时点为 `2026-10-30 00:00:00`。按订单承诺时间选到期队列；不按观察期起点截掉早到的验收，合法的期前验收仍可满足期内承诺。起点含、终点不含；承诺时点的合格验收计入，晚一秒不计入。
- 一张订单只有一个共同承诺时间，由所有商品行继承。所有保留商品行都是有效行。本简化模型支持整单取消，不模拟单行取消、变更承诺、退货或质检回退。真实系统需先冻结这些口径，不能直接套用。
- 每 SKU 只有一个基本单位：大米、鸡肉、番茄、土豆、面粉以 kg，鸡蛋以个，牛奶与食用油以升；服装以件。教学输入使用整数数量；全角数字被拒绝；小数业务需要先约定精度及统一整数最小单位，例如克。不能把不同 SKU 或不同单位的数量直接合成总体满足率。
- 正订货量是输入要求，0 或负数阻断。零分母通过“某 SKU 没有纳入队列的订单行／某地点没有到期订单”测试，不伪造零数量订单。
- 验收表的 `qualified_qty` 只表示已确认合格的验收量，不是收到数量。0 表示本条事件没有贡献合格数量。本包不提供原始到货量和不合格明细，也不计算合格率。
- `on_hand` 在本包明确表示可用库存，不再另外模拟冻结、待检等状态；恰为0才记缺货，不是低于安全库存就记缺货。
- 验收事件身份为 `(scenario, event_id)`。同身份、全部字段一致视为重传，去重；同身份字段冲突则阻断整次运行。不同事件的合法分批保留。绝不按数量相同删除不同事件。
- 主键重复、孤儿引用、未知状态、格式错误等阻断整次运行，不悄悄删除后报一个更好看的指标。快照负数、未知、缺行按明确分类披露，不进有效快照分母。

## 六表与 SQL 路径

`sites.csv` 地点；`skus.csv` SKU 及单位；`orders.csv` 订单；`lines.csv` 订单行；`receipts.csv` 合格验收事件；`snapshots.csv` 每日库存快照。

业务案例由 `scenario` 隔离。订单唯一键为场景＋单号，订单行、SKU、地点、事件也带场景；快照唯一键为场景＋地点＋SKU＋时点。订单必须至少一行。

计算顺序：
1. `eligible_orders` 冻结有效、已到期、承诺时间位于观察期的订单。
2. `receipt_unique` 消除完全相同的重复上报。
3. `line_result` 按订单行累计承诺前合格验收量，防止连接放大订货量。
4. `order_result` 用所有商品行是否足量判断整单，`metric_otif` 按地点汇总。
5. `metric_fill` 逐行将合格量封顶为订货量，再按 SKU 与单位汇总。
6. `expected_grid` 明确每天18点应有一次快照，`snapshot_result` 分类，`metric_stockout` 输出零库存比例及覆盖率。

SQL 中地点沿用统一 `site_id`，禾味代表门店，服装代表生产交付接收点，不把服装案例冒称零售门店。

## 数据量和手算答案

两个案例各有 2 个地点、8 个 SKU、14 天每日快照，应有 224 条；合计应有 448 条，实收 446 条。每个案例首地点首 SKU 缺 1 条、未知 1 条、负数 1 条。服装的 8 个 SKU 是为了演示“无到期订单时仍保留维度并返回 NULL”，不是声称都有订单。订单共9张、订单行11行；验收原始15条，去除2条完全相同重传后13条。数量信息均为模拟。

### 匿名服装企业

- AO1：AS01（TEE-M上衣M）100件，分两批60＋40按时合格；AS02（PANT-M裤子M）50件，按时40、晚1秒10。整单未通过。
- AO2：AS01 100件，按时合格120，计算数量满足率时该行只记100。整单通过。
- 接收点 A01 OTIF=1/2=50%；A02没有到期订单，分母0、结果NULL。
- AS01数量满足率=200/200=100%；AS02=40/50=80%。其余SKU分母0、结果NULL。

### 禾味

- HO1，门店H01：HS01大米10kg，按时6＋4；HS02鸡肉5kg，按时4。整单失败。
- HO2，门店H01：HS01大米10kg，按时12。整单通过，数量按行封顶。
- HO3，门店H01：HS01大米10kg，晚1秒到10。整单失败，按时量0。
- HO4取消，排除；HO5承诺10月31日，尚未到期，排除。排除原因保存到结果。
- HO6，门店H02：HS05土豆8kg，在承诺时刻合格8。通过。
- HO7，门店H02：HS06牛奶4升，合格验收量0。失败。
- H01 OTIF=1/3=33.33%；H02=1/2=50%。HS01数量满足率=20/30=66.67%；HS02=4/5=80%；HS05=8/8=100%；HS06=0/4=0%。其他SKU为NULL。
- H01×HS01：14个预期快照，2零库存、9正库存、1缺行、1未知、1负数。缺货率=2/11=18.18%，有效覆盖率=11/14=78.57%。H02×HS02最后一天为0，其缺货率为1/14；其余网格全为正库存。

缺货率描述被观测到的有效快照，不能解释为缺货时长或销售损失。服装快照采用同样的质量测试布局，不能将两个案例的数量合并。

## 输出及证据

- `metric_otif.csv`、`metric_fill.csv`、`metric_stockout.csv`：三项结果，含分子、分母、原始比例；快照结果另有预期数、缺失、未知、负数及覆盖率。
- `line_result.csv`、`order_result.csv`：可逐行核查中间量。
- `excluded_orders.csv`、`snapshot_quality.csv`：排除及质量明细。
- `audit.json`：Python与SQLite版本、统计范围、统计时点、时区、模拟声明、输入行数、重复事件去重数、输入与SQL的SHA-256。与本次输出一同保存，不能只截一个百分比。

测试包括明确手算、独立Python逐事件参考算法，以及跨场景同号隔离、零行CSV保留表头、反例输入、时间边界、顺序不变性、不同身份的合法分批、全缺快照、结果拒绝覆盖。通过这些测试仅支持本教学契约，不代表生产上线认证。
