# 预测实战教程 基础与经典方法

本文面向有供应链与产品经验、希望补齐预测方法的学习者。你不需要先学完高等数学，但需要愿意把业务问题写清楚，用小样本亲手算一次，再用按时间切分的实验验证判断。

这部分的目标是完成一条最小闭环：定义预测对象，准备数据，建立基线，公平比较，理解回归，理解经典时间序列，写出一份别人能够复核的实验结论。后续再增加树模型、概率预测、跨商品建模、新品预测和补货决策。

**案例声明。** 禾味是虚构餐饮企业，设有2家门店、8个食材SKU。下文14天数据是为了手算而单独构造的教学样本，不是已有文章或180日实验的截取，不代表真实企业表现。另设匿名服装企业案例，只用于说明不同业务结构。所有手工设定系数、模拟结果和假设都会标明。

## 第1章 先弄清楚你说的预测是什么

### 1.1 把预测写成一句可以执行的话

“我要预测销量”还不能直接成为一个模型需求。至少要补齐以下内容：

- 对象：哪个门店、哪个商品、哪个渠道？
- 目标：订单量、支付销量、净销量、食材净耗用量，还是未受缺货限制的需求量？
- 粒度：每小时、每天、每周，还是每月？
- 预测范围：明天一天，未来7天每天，还是未来7天合计？
- 发出时间：今天什么时候生成结果？
- 可用信息：在那个时间点，哪些数据已经到达？
- 后续动作：谁使用结果，决定采购、调拨、排班还是生产？

禾味的入门任务可以写成：

“每天完成营业结算后，在次日采购截单前，使用截至当时已到达的数据，预测每家门店、每个食材SKU次日净耗用量，单位kg，先为采购人员提供参考，不直接自动下单。”

这里的“已到达”很重要。某条记录的业务日期是今天，并不意味着模型运行时就能看见它。如果盘点两天后才补录，历史回测也要尊重这个延迟。

如果实际采购必须在当日18点截止，而全天净耗用量到23点才确定，就不能把“当天完整耗用量”作为18点的输入。此时应使用截至18点的数据、前一完整营业日数据，或先预测当天剩余耗用。

### 1.2 五个容易混用的数字

**需求量**是顾客在给定价格、服务等条件下想买的数量。**销量**是实际成交的数量。**耗用量**是生产或服务过程中实际使用的物料数量。**采购量**是结合库存、到货、包装和约束后下单的数量。

**销售额**则是用金额计量的成交结果，不能和“销量多少件”混用。若只有一种商品、统一成交价且暂不考虑退货，销售额=成交单价×销量。例如10件衣服每件100元，销售额为100×10=1000元；次日每件80元、卖12件，销售额为80×12=960元。销量增加2件，销售额反而减少40元，因此销额下降不等于需求下降。多种商品要逐项计算“成交单价×成交数量”再相加；有优惠、退款或税费时，还要先写清是否扣券、是否扣退货、是否含税、币种以及按支付日还是确认收入日统计。

若任务是采购补货，通常先关心某个SKU多少件、食材多少kg；若任务是收入计划，可以直接预测已明确定义的金额。两者也能联合建模，但不能把“销售额÷吊牌价”自动当作真实需求，因为成交折扣、商品组合和缺货都可能变化。

例如，明天预计售出100份鸡腿饭，每份标准净用鸡腿肉0.18kg，那么按配方计算的理论净需求是18kg。若需要从毛料换算到净料，且出成率为90%，相应毛料需求为18÷0.9=20kg。这里必须先确认0.18kg是净料还是毛料，不能再重复计算损耗。

采购量还要扣除可用库存、考虑已下单未到货、保质期、最小起订量和交期。即使预测需求为20kg，也不等于一定要采购20kg。本文前半部先把需求或耗用预测学清楚，补货计算另行处理。

服装企业也一样：顾客想买10件M码，门店只剩4件，最终卖出4件。把4件当作完整需求，会让模型认为这款商品不畅销。日销量至少应与可售库存、断码和营业状态一起看。

### 1.3 线性回归与时间序列不是互斥选项

“线性回归”主要描述模型怎样建立输入和输出的关系；“时间序列”主要描述数据有时间顺序，以及过去与未来怎样关联。

如果用“过去7天销量、星期、已排定促销”预测明天销量，你可以使用线性回归，也可以使用树模型。它们都在解决时间序列预测问题。如果一条回归只研究不同门店某月的营业面积和销量关系，它可能是横截面分析，未必是在预测未来。

因此学习路径不必是“学完回归就告别回归、进入时间序列”。更实用的路径是：

1. 从不需要训练的简单规则开始。
2. 学会用一个输入解释一个目标。
3. 加入多个输入、类别信息和交互作用。
4. 加入历史滞后、趋势与季节性。
5. 再比较更复杂的非线性模型与概率模型。

### 1.4 特征 参数 目标 序列分别是什么

以“预测耗用量=截距+系数×预订份数”为例：

| 名词 | 对应内容 | 应该怎样理解 |
|---|---|---|
| 目标 y | 次日鸡腿肉净耗用量 | 你要预测的结果 |
| 特征 x | 截单时已确认的次日预订份数 | 预测时送进模型的信息 |
| 参数 | 截距和系数 | 模型从训练数据学出的数字 |
| 超参数 | 例如移动平均取3天还是7天 | 在训练过程外选择或通过验证集选择的设置 |
| 一条序列 | S01门店、K01食材按日排列的耗用量 | 同一对象随时间变化的数据 |
| 多条序列 | 2家门店×8个SKU的16条序列 | 不等于有16个目标特征，也不等于有16个模型 |

“单一参数到多参数”在日常交流中常常实际指“一个特征到多个特征”。单特征线性回归通常已经有截距、斜率两个参数。把这两个概念分开，后续读模型文档会轻松很多。

还要分清三个方向：

- 多特征：用价格、促销、星期等共同预测一个销量。
- 多目标：同一个模型同时输出销量与退货量，或多个未来时点的预测。
- 多序列：同时处理多个门店、商品或尺码的历史记录。

对服装来说，“多类别”也有两层意思：把颜色、品类、渠道当作输入类别，或者同时预测多个品类。前者是特征编码问题，后者是多序列、分组或层级预测问题。

**本章练习。** 把你熟悉的一个预测需求改写成一段业务合同。要求写清目标、单位、粒度、预测范围、发出时间和使用人。暂时不写算法名称。

**验收标准。** 另一个人读完后，能够准确知道应该查哪张事实表，哪一列是目标，以及生成结果时能看见哪些数据。

## 第2章 先把数据整理成一条可信的时间线

### 2.1 一行到底代表什么

禾味的长表约定为“一天×一家门店×一个食材SKU”一行。若2家门店、8个SKU都连续经营14天，应有2×8×14=224行。未来扩展到180天，完整日期骨架为2×8×180=2880行。这个行数只是结构检查，不代表样本之间互相独立，也不保证数据量足够训练复杂模型。

建议保留以下字段：

| 字段 | 含义 | 核查要点 |
|---|---|---|
| business_date | 业务日期 | 按门店营业日定义，说明时区和跨午夜规则 |
| store_id | 门店标识 | 稳定且唯一，不把店名更名当作新门店 |
| sku_id | 食材SKU标识 | 规格变化和新旧SKU映射有版本 |
| used_kg | 已确认净耗用量 | 目标列，口径与盘点调整分开 |
| is_open | 是否营业 | 闭店与无需求区分 |
| stockout_flag | 是否发生缺货 | 不把受限观测直接当作完整需求 |
| promo_plan | 预测时已知促销计划 | 保存当时版本，不用事后修订覆盖历史 |
| reservations | 截止时已确认预订 | 保存截止时间与取消规则 |
| known_at | 数据可被模型读取的时间 | 防止延迟补录造成穿越 |

实际系统可以拆表存储，但实验数据集必须保留这些信息之间的关系。SKU字段只标识对象，不会自动告诉模型鸡腿肉和米饭谁更相似。

### 2.2 零 缺失 缺货是三种情况

假设某天used_kg这一格没有数值，不能马上填0：

1. 门店正常营业，系统记录完整，确实没有耗用：可能是真实0。
2. 门店闭店：可以记录实际耗用为0，但要保留闭店标记。预测未来闭店日可由业务规则处理。
3. 接口掉数或盘点未完成：这是缺失，不等于0。
4. 食材断供或菜品停售：实际耗用被供应限制，不等于潜在需求为0。

若目标是“在实际供给约束下会卖多少”，库存约束本身就是预测条件；若目标是“货源充足时顾客会买多少”，就涉及被截断需求的估计。这是两个任务，不应只改一个字段名就混用。

补值也会影响评价。用估计值修补了目标以后，不能把它称为已观测的真实需求。应保留原始列、修补列、修补原因，并分别报告可直接评价的样本与受限样本。

只有两周数据时，可以演示一周周期的含义，但不足以证明这个周期长期稳定，更不能验证年季节性或春节效应。180天也未覆盖完整年度，不能据此可靠学习年度重复模式。

### 2.4 先画四张图 再谈选模型

- 按日折线图：看趋势、断点、异常高峰和漏数。
- 按星期分组的分布图：看同一星期是否有规律，也看组内波动。
- 目标与候选特征的散点图：例如预订份数与耗用量。
- 缺失、缺货、促销标记叠加图：判断异常是数据问题还是业务事件。

图形只能提供线索。某一天销量高且打折，不能仅凭这一点认定打折造成增长。也不能因为某列与目标的简单相关系数很小，就断定它在多特征模型中完全没用。

**本章练习。** 找出一条“日期没有缺口但数据仍不能直接训练”的例子。

**参考答案。** 所有日期都有数值，但缺货日销量被当作完整需求；或者促销字段被事后修改，回测拿到了预测时不知道的促销结果。

## 第3章 用最少的数学做出第一组预测

### 3.1 先认识五个符号

- y_t：第t天实际值。下标只是日期编号。
- ŷ：预测值，读作“y帽”。
- ŷ_(t+1|t)：站在第t天结束时，对第t+1天的预测。
- e=实际值−预测值：本文统一采用这个误差方向。
- Σ：把指定的一组数相加。

例如，第8天实际22kg，提前预测20kg，则e=22−20=2kg，表示低估2kg。如果预测24kg，则e=−2kg，表示高估2kg。

绝对值|e|只关心偏差有多大，2和−2都变成2。平方e²也去掉正负，但会让大错误获得更大权重。两个错误是1和5时，绝对误差合计6，平方误差合计26；两个错误都是3时，绝对误差合计仍为6，平方误差合计却是18。

### 3.2 昨日法

规则：明天等于今天。

公式：ŷ_(t+1|t)=y_t。

站在第14天结束时，第15天预测为30kg。

它没有估计参数，容易理解，也能迅速跟随水平变化。但周日30kg直接用来预测周一，可能忽略周内规律。一个复杂模型如果连昨日法都比不过，就需要说明为什么仍值得使用。

### 3.3 过去7日移动平均

规则：取最近7个完整营业日的平均值。

站在第14天结束时：

ŷ_15=(22+24+23+25+32+36+30)÷7=192÷7≈27.43kg。

这里“7日”是窗口长度，不是向未来预测7天。一个7日移动平均可以用来做次日预测，两者不要混淆。

若改成3日移动平均，则：

ŷ_15=(32+36+30)÷3≈32.67kg。

短窗口更快响应最近变化，也更容易把周末高峰延续到周一。长窗口通常更平滑，但面对需求水平突然变化可能反应较慢。窗口应该通过历史验证选择，而不是因为7看上去恰好是一周就直接固定。

### 3.4 加权移动平均

希望最近一天更重要，可以给最近三天从旧到新的权重0.2、0.3、0.5。权重应加起来等于1：

ŷ_15=0.2×32+0.3×36+0.5×30=32.2kg。

这一组权重是教学设定，不是自动最优。如果尝试很多权重后选择表现最好的一组，选择过程只能使用训练或验证数据，不能反复查看最终测试集。

### 3.5 上周同日法

规则：下周一参照本周一，下周二参照本周二。

对于日数据的一周周期，次日预测公式为ŷ_(t+1|t)=y_(t+1−7)。因此第15天预测使用第8天22kg。

它保留了星期结构，特别适合作为存在稳定周内规律时的基线。不过节假日错位、调休、换季或经营变化都可能让“上周同日”失去代表性。服装中“去年同期”还会遇到新品替代、节日日期移动以及同款已退市的问题，不能机械按日期取值。

均值法、昨日法和季节性朴素法都是常用预测基准。这里的具体数据、算式与业务解释为独立教学设计。方法索引见[Forecasting Principles and Practice 第5章](https://otexts.com/fpp3/toolbox.html)。

### 3.6 为什么现在不直接加2kg

你已经看见第二周每天都比第一周多2kg，很容易给第15天写出22+2=24kg。这可以作为一个新假设，但此时还没有看到第15天实际值，不能宣布它有效。

更严重的错误是：看完第8至14天以后，把“每周增长2kg”的规律拿回去改写第8天预测，再与当时只知道前7天的方法比较。这样做等于把答案塞回试卷。

合理做法是，在第14天记录“同周法加增长修正”这个新候选，从之后的新时间段开始公平验证。真实数据中，增长修正本身也需要估计窗口和稳定性检查。

**动手做。** 在Excel或WPS中，A列放日序号，B列放实际耗用，第2行是第1天。第16行是待预测的第15天：

- 昨日法：`=B15`
- 7日移动平均：`=AVERAGE(B9:B15)`
- 3日移动平均：`=AVERAGE(B13:B15)`
- 加权3日平均：`=0.2*B13+0.3*B14+0.5*B15`
- 上周同日法：`=B9`

**本章验收。** 你应该能算出30、27.43、32.67、32.2、22，并说明它们使用的信息完全相同，但归纳历史的方法不同。此刻没有第15天实际值，不能判定谁赢。

## 第4章 回测让你知道方法究竟有没有用

### 4.1 回测就是回到过去作出当时能够作出的预测

对14天样本，我们先做逐日滚动的次日预测：

- 在第7天结束时，只看第1至7天，预测第8天。
- 第8天实际值到达后，在第8天结束时预测第9天。
- 一直重复到第14天。

评估区间是第8至14天；每次预测步长都是1天。这不是站在第7天一次预测整整一周。两种任务能使用的信息不同，不能把成绩混为一谈。

### 4.2 用同一张评分表比较

| 目标日 | 实际kg | 昨日法kg | 上周同日法kg | 7日移动平均kg |
|---|---:|---:|---:|---:|
| 8 | 22 | 28 | 20 | 25.43 |
| 9 | 24 | 22 | 22 | 25.71 |
| 10 | 23 | 24 | 21 | 26.00 |
| 11 | 25 | 23 | 23 | 26.29 |
| 12 | 32 | 25 | 30 | 26.57 |
| 13 | 36 | 32 | 34 | 26.86 |
| 14 | 30 | 36 | 28 | 27.14 |

表中预测显示两位小数，评分使用未四舍五入的数值。不要把展示精度当作模型精度。

昨日法的误差依次是−6、2、−1、2、7、4、−6kg。绝对误差合计28kg，实际总量为192kg。

上周同日法每天的误差都是2kg。绝对误差合计14kg，但这14kg全部来自低估，不存在高估与低估抵消。

### 4.3 四个先学会就够用的指标

**MAE 平均绝对误差。** 计算每次偏差的绝对值，再取平均：

MAE=Σ|实际−预测|÷预测次数。

昨日法MAE=28÷7=4kg。可以读成：“在这7次次日预测里，每次平均偏差4kg。”它与目标单位一致，容易和业务讨论。

**RMSE 均方根误差。** 先平方，求平均，最后开平方：

RMSE=√[Σ(实际−预测)²÷预测次数]。

昨日法平方误差合计146，因此RMSE=√(146÷7)≈4.57kg。它对少数大偏差更加敏感。如果一次严重短缺比多次小偏差更难接受，可以把它作为补充，但最终仍应检查真实成本。

**WAPE 加权绝对百分比误差。** 本文在实际值非负的口径下采用：

WAPE=Σ|实际−预测|÷Σ实际。

昨日法WAPE=28÷192≈14.58%。上周同日法WAPE=14÷192≈7.29%。它不是“每次误差百分比的简单平均”，也不是“预测正确的概率”。不建议把1−WAPE直接包装成普遍意义的“预测准确率”。

如果一个评估分组的实际总量是0，WAPE未定义，不能随意报成0%。应单独报告绝对误差与零需求样本情况。若目标允许负值，例如净退货量，要重新约定分母和评价方式，不能机械沿用这一定义。

**Bias 平均有符号误差。** 本文定义为：

Bias=Σ(实际−预测)÷预测次数。

大于0表示平均低估，小于0表示平均高估。不同系统可能用相反方向，所以报表必须写清定义。平均低估可能增加缺货风险，但是否真的缺货还取决于库存与补货策略。

为避免与后续专项的百分比偏差混淆，这里的量也称ME（mean error，平均误差），单位kg，方向为实际减预测。另一个常用量“相对预测偏差率”定义为Σ(预测−实际)/Σ实际，单位为百分比，正值表示高估。两者名称、方向和单位都应同时标出，不能在同一图里只写Bias。

| 方法 | MAE kg | RMSE kg | WAPE | Bias kg |
|---|---:|---:|---:|---:|
| 昨日法 | 4.00 | 4.57 | 14.58% | 0.29 |
| 7日移动平均 | 3.84 | 4.58 | 13.99% | 1.14 |
| 上周同日法 | 2.00 | 2.00 | 7.29% | 2.00 |

这个结果支持的结论是：“在这个刻意带有周周期的7次教学回测中，同周法的绝对误差更低，但持续低估。”它不支持“同周法适用于所有餐饮企业”，也不支持“预计真实业务能降低一半损耗”。

### 4.4 为什么不优先用MAPE

MAPE先计算每一行|实际−预测|÷实际，再平均。实际为0时无法直接计算，实际接近0时比值会非常大。例如实际1件、预测3件，误差为200%；实际100件、预测102件，误差为2%，虽然两次都偏了2件。

服装尺码SKU或低频食材经常存在0销量日，MAPE会让评价失真或无法计算。WAPE缓解了单行0值问题，但它更受大销量对象影响，不能代表每个SKU都表现不错。MAE、RMSE与百分比误差的基本定义和零值限制见[Forecasting Principles and Practice 第5章的评估部分](https://otexts.com/fpp3/toolbox.html)。

同时预测多店多SKU时，至少报告三层结果：全体汇总指标、门店或商品分组指标、低量与高量对象分组指标。不同食材都以kg计量，也不意味着它们每kg短缺或报损的经济成本相同。

### 4.5 未来7天一次预测与每天更新要分开

假设站在第7天要一次生成第8至14天的预测：

- 昨日法可以把28kg延续到7天。
- 同周法可以直接重复第1至7天的星期模式。
- 移动平均若做递推，就必须把先前预测值放入后面的窗口，而不能偷用尚未发生的实际值。

如果站在第7天，却给第9天的预测用了第8天真实耗用，那就是用更容易的“每天更新”任务伪装成“提前一周预测”。应在每条结果里保存origin_date、target_date、horizon和model_version。

### 4.6 统一180天切分并识别已经暴露的测试区间

180天实验统一采用112天训练、28天验证、40天历史测试的边界：

- 第1至112天：初始训练区间。
- 第113至140天：验证区间，用于比较特征、窗口和模型设置。
- 第141至180天：历史已暴露测试区间，用于复现、复核和诊断既有结果，不能再称为未见过的独立最终测试。

“已经暴露”是指开发者已经看过这段数据或成绩，并可能据此形成模型、特征或参数选择。即使文件仍叫test，或者把预测重新跑一遍，它也不会自动恢复独立性。本文14天手算样本与这份180天实验仍是两个不同数据集，不能拼接或互称截取。

若任务是每周生成未来7天预测，验证起点可用第112、119、126、133天，正好覆盖第113至140天。历史复核区间可用第140、147、154、161、168天作为起点，覆盖第141至175天的5个完整7天批次；剩余第176至180天只能作为从第175天起点出发的1至5步部分结果，单独标明步长与样本数，不能伪装成完整第6周的7步成绩。若任务是每天更新次日预测，则可在第140至179天逐日起算，评价第141至180天的全部40次预测。两种任务分别报分，不混算。

每个历史起点只能使用当时已知的数据。是否允许每周重新训练，也要提前写定。如果生产方案确实每周更新训练数据，评价时可以按固定规则纳入已经发生、已经到达的历史记录。但看过成绩后又更换特征或调整超参数，再在同一时间段报告结果，只能称为进一步的开发或历史复核。

需要评价新的独立泛化效果时，应另生成并保护一份尚未查看的模拟测试序列，或收集后续新时间段数据。先锁定数据生成或采集规则、模型选择与评价协议，再揭开测试；不能反复选择随机种子直到得到好成绩。新的模拟测试也只能检验指定生成机制下的表现，不能替代真实业务验证。

所有门店与SKU应按共同的时间边界切分。不要把整个长表随机抽80%训练、20%测试，否则同一天其他门店、未来星期或同一对象未来记录可能进入训练。另有“新店泛化”目标时，还需要专门保留未见过门店进行检验，这与普通时间外推是不同实验。

时间滚动验证只允许历史预测未来。工具使用时还要注意采样间隔与测试持续时间的一致性，见[scikit-learn TimeSeriesSplit文档](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)。对多门店长表，通常应按唯一日期构造切分，再映射回记录，而不是直接按任意行顺序切。

### 4.7 五种常见的数据穿越

1. 用未来实际天气代替当时可见的天气预报。
2. 预测明天时，把明天总订单数作为输入。
3. 先用全部数据计算均值、补缺或标准化，再切训练测试。
4. 计算过去7天平均时，窗口包含了待预测当天的目标。
5. 用后续盘点、促销修订或商品最终生命周期标签回填过去的特征。

正确顺序是先切分，再在训练区间学习处理规则，最后将同一规则应用于后续区间。每轮滚动实验都应重新遵守这条顺序。官方防泄漏说明见[scikit-learn Common pitfalls](https://scikit-learn.org/stable/common_pitfalls.html)。

### 4.8 电子表格评分做法

假设A2:A8是真实值，B2:B8是某模型预测值：

- C2写=A2-B2，向下填充，得到有符号误差。
- D2写=ABS(C2)，向下填充，得到绝对误差。
- E2写=C2^2，向下填充，得到平方误差。
- MAE：`=AVERAGE(D2:D8)`
- RMSE：`=SQRT(AVERAGE(E2:E8))`
- WAPE：`=SUM(D2:D8)/SUM(A2:A8)，将单元格设置为百分比。`
- Bias：`=AVERAGE(C2:C8)`

**本章练习。** 模型A的MAE是2kg、Bias是2kg；模型B的MAE是2kg、Bias是0kg。是否可以说两者同样好？

**参考答案。** 只能说平均绝对偏差相同。A持续偏低，B可能高低抵消。两者对库存的影响可能不同，还应看误差分布、发生在哪些SKU以及采购策略。Bias为0也不代表每次都准确。

## 第5章 从一个特征开始理解线性回归

### 5.1 把一条直线看作一条计算规则

设x为“预测发出时已确认的次日套餐预订份数”，y为“次日鸡腿肉净耗用量kg”。先使用：

ŷ=a+b×x。

a是截距，b是斜率。b的单位是kg/份：在这条拟合规则中，预订增加1份，预测耗用增加b kg。它不是自动等同于配方BOM，更不是增加1份预订必然造成的因果效果。

下面4个观测是单独构造的回归手算数据，不是前面14天数据的另几列：

| 观测 | 已确认预订x 份 | 实际净耗用y kg |
|---|---:|---:|
| A | 100 | 20 |
| B | 120 | 23 |
| C | 140 | 27 |
| D | 160 | 30 |

模型训练要做的事是：找到一组a、b，使这4个点与直线之间的偏差尽量小。普通最小二乘使用“偏差平方和最小”作为目标，参见[scikit-learn LinearRegression文档](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LinearRegression.html)。

### 5.2 先算两个平均数

x的平均数为(100+120+140+160)÷4=130份。

y的平均数为(20+23+27+30)÷4=25kg。

把每个观测减去平均值，再做下表：

| x | y | x−130 | y−25 | 两项相乘 | (x−130)² |
|---:|---:|---:|---:|---:|---:|
| 100 | 20 | −30 | −5 | 150 | 900 |
| 120 | 23 | −10 | −2 | 20 | 100 |
| 140 | 27 | 10 | 2 | 20 | 100 |
| 160 | 30 | 30 | 5 | 150 | 900 |
| 合计 |  |  |  | 340 | 2000 |

一元线性回归的斜率可以这样求：

b=Σ[(x−x均值)×(y−y均值)]÷Σ(x−x均值)²=340÷2000=0.17。

Σ遍历这4个观测。分子单位是份×kg，分母是份²，相除得到kg/份；截距a的单位为kg。这个闭式解适用于带截距的一元普通最小二乘，前提是x不全相同。若4个x都等于130，则分母为0，斜率不能由这些数据唯一确定，不应强行输出0。最小二乘的几何目标本身不要求先假设正态分布；若要进行置信区间或显著性推断，还需额外统计条件。

分子表示两者偏离各自平均值时是否倾向于同向变化；分母用于按x自身变化的尺度进行换算。此刻不需要记住推导，只需知道它把一组点的共同变化压缩成一个斜率。

然后算截距：a=y均值−b×x均值=25−0.17×130=2.9。

因此模型为：ŷ=2.9+0.17x。

### 5.3 检查拟合结果

| x | 实际y | 拟合ŷ | 实际−拟合 |
|---:|---:|---:|---:|
| 100 | 20 | 19.9 | 0.1 |
| 120 | 23 | 23.3 | −0.3 |
| 140 | 27 | 26.7 | 0.3 |
| 160 | 30 | 30.1 | −0.1 |

平方误差和=0.1²+0.3²+0.3²+0.1²=0.2。训练MAE为0.2kg。

这里使用参与训练的4个点来检查拟合，误差叫训练残差。它不等同于提前预测未来的误差。这个样本故意接近直线，而且只有4个点，不能拿0.2kg当作上线后精度。

### 5.4 真正生成一个预测

若截单时已确认次日预订150份：

ŷ=2.9+0.17×150=28.4kg。

这个150在预测时已经知道，因此可以使用。若150其实是第二天最终完成的订单总数，就不允许这样直接用。你需要先预测订单数，或者换成预测时可见的预订信息，并在回测时完整模拟同样过程。

这里150位于训练范围100至160之间，属于插值。若拿它预测800份预订，则是远距离外推。厨房产能、团餐结构、菜品配比和供应约束都可能变化，不能因为公式还能算出138.9kg，就认为这个数可靠。

截距2.9是直线的位置，不应机械解释为“没有预订也一定耗用2.9kg”。样本并没有观察到接近0份的情况，截距的业务意义需要额外证据。

### 5.5 用电子表格复现

假设A2:A5放x，B2:B5放y：

- 斜率：`=SLOPE(B2:B5,A2:A5)，应得到0.17。`
- 截距：`=INTERCEPT(B2:B5,A2:A5)，应得到2.9。`
- 预测150份：`=FORECAST.LINEAR(150,B2:B5,A2:A5)，应得到28.4。`

图表中使用散点图，而不是把A、B、C、D当作等距类别的折线图。横轴是预订份数，纵轴是kg，坐标单位应写出来。

### 5.6 不用R²替代预测验收

R²描述模型对这批数据波动的拟合程度。4个点几乎排成直线，训练R²自然很高，但这不说明未来预测可靠。增加特征通常能让训练拟合更好，却可能损害未来效果。

同样，“预订与耗用正相关”可以支持预测候选特征，但不能直接推出改变预订策略的收益。预测关系和因果干预需要不同证据。[Forecasting Principles and Practice 第7章](https://otexts.com/fpp3/regression.html)专门讨论了R²的局限与相关、因果的区别。

**本章练习。** 用刚才的模型预测130份预订的耗用量；再说明为什么不能承诺“每增加100份预订，采购一定增加17kg”。

**参考答案。** 预测为25kg。17kg只是模型给出的条件关联增量，不等于已识别的因果效果；采购还受库存、交期、可替代食材与包装规格影响。

## 第6章 从多个数值到不同类型的特征

### 6.1 多元回归只是把一条规则拆成多项

真实业务不只受预订影响。加入周末、促销、门店后，可以写成：

ŷ=b0+b1×预订份数+b2×周末标记+b3×促销标记+b4×门店B标记。

ŷ单位kg；b0为截距，单位kg；b1单位kg/份；三个标记均无单位，因此b2、b3、b4单位都为kg。下标0至4只是参数编号，不是时间或乘方。把各特征乘对应系数后，所有项都转成kg才能相加。

周末、促销与门店B标记都是0或1。为了只练习“模型怎样使用多个输入”，先人为设定一组系数：

ŷ=8+0.08×预订份数+2×周末标记+3×促销标记+4×门店B标记。

**这些系数是教学假设，不是对14天数据或180天数据训练得到的结果。** 真正训练时，应由历史训练样本共同估计所有系数，再进行时间回测。

如果门店B明天是周末、有促销、已确认150份预订，则：

ŷ=8+0.08×150+2+3+4=29kg。

若所有其他条件不变，仅换成门店A，门店B标记由1变为0，预测降到25kg。这是模型内部的条件比较，不是证明把A店改名为B店就能增加4kg需求。

### 6.2 为什么不能把门店随意编码成1 2 3

如果门店A=1、B=2、C=3，再直接乘一个系数，模型就会把B与A的差异视为和C与B相同，还暗含门店之间有顺序和距离。这一般不是门店类别的真实含义。

对于带截距的普通线性回归，常见做法是选一个参考类别，其余类别各建一个0/1列。例如三种渠道：

| 渠道 | 外卖标记 | 团餐标记 |
|---|---:|---:|
| 堂食 参考组 | 0 | 0 |
| 外卖 | 1 | 0 |
| 团餐 | 0 | 1 |

若同时放截距、堂食、外卖、团餐三个标记，它们会满足“堂食+外卖+团餐=1”，产生完全线性依赖。软件可能给出某种数值解，但系数不能按唯一可识别的类别差异随意解释。参考组编码是一个清楚的处理办法。独热编码的工具行为见[scikit-learn OneHotEncoder文档](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.OneHotEncoder.html)。

类别数量很多时，独热列也会变多。新品、新店或新渠道还可能在预测时第一次出现。训练前就应确定未知类别的处理规则，不能到上线才发现系统拒绝预测。树模型或原生类别模型的编码要求也各不相同，不能把一套编码方式当作所有算法的通用规定。

### 6.3 “不同类别对促销反应不同”需要交互项

刚才的规则让A店和B店的促销增量都等于3kg。如果希望表达“B店促销可能更强”，可以加入：

交互项=促销标记×门店B标记。

再假定它的教学系数为1.5，则：

ŷ=原公式+1.5×促销标记×门店B标记。

门店B有促销时，新预测为30.5kg；A店有促销时仍加3kg；B店无促销时交互项为0。

交互项回答的是“某个因素的预测关系是否因另一个因素而不同”。服装中可对应“折扣×品类”“气温×外套品类”“渠道×价格”。如果数据里所有促销都恰好发生在周末，你很难可靠分开周末与促销各自的关系，需要更多不同组合的数据。

### 6.4 周几 价格 尺码不能采用同一种处理

| 信息 | 一种入门处理 | 需要警惕的事 |
|---|---|---|
| 价格 | 数值特征 | 历史价格可能由清库存策略决定，系数不自动是价格弹性 |
| 促销 | 0/1、类型类别、折扣深度 | 只用预测时已确认的活动版本 |
| 星期 | 类别标记 | 周日与周一相邻，但数字7与1相差6，不宜任意当直线关系 |
| 门店或渠道 | 类别编码 | 编号本身没有大小和等距意义 |
| 尺码 | 结合品类定义的类别或有序信息 | S到M与M到L未必代表同样的需求变化 |
| 温度 | 数值，可进一步加非线性关系 | 未来实际温度不可用，应使用当时预报或情景 |
| 节假日 | 已知日历、节前节后距离 | 调休和移动节日不等于普通星期模式 |
| 商品上市天数 | 数值或生命周期阶段 | 不能使用预测时尚未知的最终退市日期 |

“线性”也不意味着只能画直线。如果把x²作为额外特征，ŷ=a+b1x+b2x²仍对系数保持线性，但对x呈曲线。模型变灵活后，也更容易在样本边界外给出不合理结果。

### 6.5 多加一个特征之前先问四个问题

1. 预测发出时能拿到它吗？
2. 历史能重建当时版本吗？
3. 样本是否覆盖它的不同取值和组合？
4. 加入后是否改善相同时间回测，并值得增加数据依赖？

例如天气特征带来0.1个百分点WAPE改善，却需要一个经常延迟的外部接口，它未必值得引入第一版。反过来，促销计划若显著降低关键大促的短缺风险，即使平均指标改善不大，也可能有业务价值，需要单独分组验证。

### 6.6 正则化是给过于灵活的系数加约束

特征变多以后，模型可能用很大的正负系数互相抵消，把历史噪声拟合得很好。Ridge在拟合误差之外惩罚系数平方，Lasso惩罚系数绝对值，后者可能把部分系数压到0。

入门时先理解作用，不急着手推优化算法：模型需要在“解释历史”与“保持规则稳定”之间折中。惩罚强度是需要验证的设置。若特征量纲相差很大，通常要按训练集统计量进行缩放，使惩罚更可比；验证与测试只能沿用训练阶段学到的缩放规则。

正则化不能修复数据穿越，也不能从4个样本里制造充足证据。应先建立低特征数、可解释的基线，再比较它是否真的带来改进。

**本章练习。** 匿名服装企业有品类、颜色、门店、上市天数、折扣率和明日实际销量。哪些可以用于预测明日销量？

**参考答案。** 前五类信息在预测时可知且历史版本可重建时可以作为候选；“明日实际销量”本身是目标，不能作为输入。计划折扣可以使用，事后实际折扣若当时未确定则不能直接使用。

## 第7章 时间序列先从水平 趋势和季节性开始

### 7.1 拆开观察一条曲线

一条日耗用曲线可以先从四个角度观察：

- 水平：最近一般在什么量级，比如每天约25kg。
- 趋势：这个量级是否缓慢上升或下降。
- 季节性：是否按已知周期重复，比如每周五、六较高。
- 剩余波动：前面几部分没有解释的变化。

这是一种观察框架，不意味着现实一定能被完美分成四个独立部分。春节与开学季等事件可能会移动；促销、缺货和菜单调整也未必是随机噪声。

匿名服装企业可以同时存在周末效应、年度气候季节性和一款商品的上市生命周期。生命周期是随着上市后时间推进而变化，不一定会对同一SKU逐年重复，不能把二者混为“季节性”。

### 7.2 简单指数平滑 每次只更新一个水平

移动平均在窗口外突然丢掉旧数据。简单指数平滑则逐步降低旧观测的影响。设当前水平为l：

l_t=α×y_t+(1−α)×l_(t−1)。

次日预测为ŷ_(t+1|t)=l_t。

α取0到1之间。α越大，越重视最新实际值；越小，越平滑。为了演示，令α=0.3，初始水平l_1=y_1=20kg：

这里t是日序号，y_t是当日实际kg，l_t是看过第t天数据后的平滑水平kg，l_(t−1)是前一天水平kg；α是无单位权重。公式可改写为l_t=l_(t−1)+α(y_t−l_(t−1))：旧水平只向新观测移动α份距离。它假定仅跟踪局部水平，不能自行表达提前已知的促销或星期结构。

- 第2天更新：l_2=0.3×22+0.7×20=20.6。
- 第3天更新：l_3=0.3×21+0.7×20.6=20.72。
- 第4天更新：l_4=0.3×23+0.7×20.72=21.404。
- 因此在第4天结束时，对第5天预测21.404kg。

第5天实际是30kg，说明只追踪水平并不能提前识别本教学样本的周五高峰。继续按同一规则计算，第14天更新后的水平约29.73kg，作为第15天预测。它有平滑作用，但不会凭空学会周一回落。

只使用简单指数平滑时，从同一起点向未来多步预测通常都是当前水平。适用范围和指数平滑的组件形式见[Forecasting Principles and Practice 第8章](https://otexts.com/fpp3/exponential-smoothing.html)。α=0.3只是教学设定，实战应在训练与验证中估计或选择。

### 7.3 Holt方法 再跟踪一个趋势

如果水平持续增长，可以同时更新水平l和每期趋势b：

l_t=αy_t+(1−α)(l_(t−1)+b_(t−1))。

b_t=β(l_t−l_(t−1))+(1−β)b_(t−1)。

h步预测为ŷ_(t+h|t)=l_t+h×b_t。

新增符号b_t是每一个日步的增长量，通常口头称kg/天；α与β是无单位平滑权重，均在0到1之间，β调节趋势更新速度；h是未来日步数。日步长固定为1天，l_(t−1)+b_(t−1)实际表示“水平+趋势×1天”，因此单位一致。若换成周数据，b与h也必须改为周步，不能把日趋势直接乘周数。

读公式时先看意思：新的水平结合“本期实际”和“上期水平按趋势往前走一步”；新的趋势结合“刚刚观察到的水平变化”和“旧趋势”。

用一个独立状态演示：上期水平24kg，上期趋势0.5kg/天，本期实际26kg，α=0.3，β=0.2。

1. 先更新水平：l=0.3×26+0.7×(24+0.5)=24.95kg。
2. 再更新趋势：b=0.2×(24.95−24)+0.8×0.5=0.59kg/天。
3. 预测下一天：24.95+0.59=25.54kg。
4. 预测第3天：24.95+3×0.59=26.72kg。

这只是计算演示，不是前面14天样本的拟合结果。若长时间外推固定增长，可能越来越不合理。阻尼趋势让增长影响逐步减弱，用来表达“短期继续增长，但不永远按同样速度增长”的假设。

### 7.4 Holt Winters 加入重复的周期

如果还有一周规律，可以为周期中的位置维护季节分量。

加法季节性的直觉是“周五大约多5kg”。例如预测时点的下一期水平加趋势为25.3kg，周五季节分量为+5kg，则预测30.3kg。

乘法季节性的直觉是“周五大约比普通水平高20%”。若对应因子为1.2，则预测25.3×1.2=30.36kg。

当业务规模翻倍后，星期波动更接近固定加几kg，还是整体同比例放大，能帮助选择候选形式。但最终仍要回测。乘法模型还要求相应建模数据满足正值等条件，零值较多时不能直接照搬。

两周教学样本只能演示一周周期，不适合承担稳定估计复杂趋势和季节参数的任务。实际训练应覆盖多个相关周期，并检查经营制度是否改变。[statsmodels ExponentialSmoothing文档](https://www.statsmodels.org/stable/generated/statsmodels.tsa.holtwinters.ExponentialSmoothing.html)明确区分趋势、阻尼和加法或乘法季节组件。

ETS常用于表示以误差、趋势、季节性组件组织的一类状态空间模型。不要把所有指数平滑都简单理解成“给最近几天乘几个权重”，也不必在第一轮实验里穷举所有组件组合。

### 7.5 选模型时先看它能够表达什么

| 观察到的主要结构 | 候选起点 | 还需要比较的基线 |
|---|---|---|
| 水平较稳定，无明显周期 | 简单指数平滑 | 均值、昨日法 |
| 水平缓慢变化 | Holt或阻尼趋势 | 移动平均、昨日法 |
| 稳定的一周周期 | 季节性指数平滑 | 上周同日法 |
| 促销和节假日影响很强 | 含外部特征的模型 | 同周法加明确业务规则 |
| 大量0，偶尔出现需求 | 先作为间歇需求专门处理 | 不直接套用普通平滑结论 |

这张表是候选筛选规则，不是性能保证。某个模型能够表达季节性，不代表它在短样本或制度变化时一定胜过简单同周法。

**本章练习。** 如果α=1，简单指数平滑退化成什么方法？如果α接近0，又有什么表现？

**参考答案。** α=1时水平等于最新实际值，次日预测就是昨日法。α接近0时新数据的影响很小，预测变化很慢；这不是自动更稳健，只是更不敏感。

## 第8章 看懂ARIMA以及回归与时间序列怎样结合

### 8.1 自回归 用自己的过去预测自己

普通回归可以使用预订份数，自回归把自己的历史值当作输入。例如：

y_t=c+φ×y_(t−1)+ε_t。

c是常数，φ是上期值的系数，ε是当前还无法解释的随机扰动。用一个独立教学模型：y_t=10+0.6y_(t−1)+ε_t。

本节y、c、ε单位都是kg，φ无单位，t是日序号；点预测时把未来扰动的条件均值设为0，而不是断言未来没有波动。简单AR(1)在|φ|<1、扰动符合相应条件时有稳定均值，若φ接近或超过1则不能沿用下文长期回落的解释。

如果最近实际是30kg，则下一天的点预测为10+0.6×30=28kg。再向前一天时，尚未得到第一天实际值，所以用预测值递推：10+0.6×28=26.8kg。

你已经看见自回归与多步预测的联系。不能第二步偷偷换用尚未发生的实际值。这个模型在相应稳定条件下围绕25kg的长期均值波动，因为25=10+0.6×25。

### 8.2 差分 先预测变化再加回去

原序列是20、22、21、23时，相邻差分是2、−1、2。

一阶差分Δy_t=y_t−y_(t−1)，把“今天是多少”改成“今天比昨天多多少”。如果最近值23kg，模型预测下一次变化为1.5kg，那么下一期水平预测就是24.5kg。

季节差分则比较相隔一个周期的值。例如一周周期为7，季节差分为y_t−y_(t−7)。教学样本第8至14天的季节差分都等于2kg。

差分是帮助处理某些非稳定变化的一种办法，不是所有序列必须进行的固定步骤。过度差分也可能放大噪声、引入不必要的结构。不能因为已经学了差分，就对所有数据差两次。

### 8.3 ARIMA里的MA不是滑动平均预测

前面“过去7天移动平均”是直接对历史观测取平均。ARIMA中的MA部分使用过去的随机扰动项来描述当前变化，它与移动平均基线不是同一个概念。

可以先把它理解为：模型考虑“上一次出现了怎样的意外偏差”，并估计这种意外是否还会延续影响。但严格说，模型中的扰动并非直接观测值，需要在拟合过程中估计，不能把任意一组业务报表误差直接塞进去。

### 8.4 三个数字怎样读

ARIMA(p,d,q)中：

- p：自回归部分使用的阶数。
- d：非季节差分次数。
- q：移动平均误差部分的阶数。

比如ARIMA(1,1,1)，可以先理解为“先做一次差分，再用一个滞后变化和一个滞后扰动描述差分后的序列”。概念公式可以写成：

Δy_t=c+φΔy_(t−1)+ε_t+θε_(t−1)。

Δ表示“相邻两期相减”，Δy与c、ε单位同为kg，φ、θ为无单位系数；θ乘的是上一期模型扰动，不是上一期销量。完整手算一个教学状态：最近变化Δy_(t−1)=2kg，估计上一期扰动ε_(t−1)=−1kg，设c=0.5kg、φ=0.4、θ=0.2，则下一次变化的点预测=0.5+0.4×2+0.2×(−1)=1.1kg（未来ε_t的条件均值为0）。若最近水平23kg，则还原的水平预测=23+1.1=24.1kg。这里仅演示已给参数怎样计算，不是完成了ARIMA拟合，也不代表该参数设定适合任何数据。

实际软件对常数、漂移和趋势的参数化方式可能不同，不能看到一个c就直接套用同样的业务解释。季节ARIMA还会增加季节阶数和周期m；日数据的一周周期常设m=7，月数据的一年周期常设m=12，但应由数据频率与业务周期决定。

ARIMA、季节组件与外生变量的接口定义可查[statsmodels ARIMA文档](https://www.statsmodels.org/stable/generated/statsmodels.tsa.arima.model.ARIMA.html)。第一轮实验不需要手推极大似然估计，但必须知道模型使用哪些信息、输出怎样生成、回测有无穿越。

### 8.5 ARIMAX或动态回归 把两条学习线接起来

回归可以解释促销、预订和星期。若回归后的残差仍明显连续几天偏高，说明剩余误差还有时间结构。动态回归可以用外部特征解释一部分，再用ARIMA结构描述剩余变化。

一种概念表达是：

耗用量=促销与预订等特征的回归部分+具有时间相关性的误差部分。

这种组合不会解除输入可得性的要求。如果模型需要未来7天促销、天气或价格，就必须在预测起点准备相应计划、预报或情景。拿真实未来天气做出的结果，可以用于“如果天气已知”的条件分析，却不能冒充当时可实现的业务预测。

### 8.6 对ARIMA做四项检查

1. 拟合过程是否收敛，有没有错误或警告？
2. 预测有没有不合理的负值或远距离爆炸？
3. 残差是否仍有明显的星期或连续偏差结构？
4. 在同样起点、步长、数据口径下，是否超过了同周法等基线？

销量或耗用出现负预测时，不能悄悄把它截断为0后继续沿用原成绩。若决定采用非负截断，它就是预测流程的一部分，回测也要采用同样规则；同时还应检查分布假设、变换和模型选择是否适合该目标。

AIC、BIC等模型选择指标可以帮助在特定统计假设下比较候选，但不能替代面向实际预测任务的时间回测。一次拟合不报错，也不等于模型适合生产。

**本章练习。** “SARIMA用了季节性，所以一定比上周同日法准确”，这句话有什么问题？

**参考答案。** 两者都能利用周期信息，但复杂模型需要估计更多结构。样本短、周期不稳定或设定错误时，它可能更差。必须在相同可用信息和时间协议下比较，不按模型名字排序。

## 第9章 完成一次你能够解释的基础实验

### 9.1 先限定实验边界

第一轮可以只选一个门店、一个食材SKU，预测次日耗用。目标是证明整条流程正确，不是证明这个SKU的最优算法能代表全部业务。

按以下顺序进行：

1. 写出第1章的预测业务合同。
2. 整理日期骨架，检查缺失、闭店、缺货和单位。
3. 画出历史图，提出少量可检验的候选规律。
4. 先写固定的时间切分、更新频率和指标。
5. 建立昨日法、同周法、移动平均三种基线。
6. 加入一个低特征数回归与一种合适的平滑模型。
7. 只在验证区间选方法，记录失败与警告。
8. 锁定流程后，在另行保护的未暴露测试数据上评价，输出逐条预测和分组结果。若复用第141至180天，只报告历史复核，不称为新的独立最终测试。

如果没有足够历史，不需要勉强把所有模型都跑一遍。14天适合练算术和数据流，180天可支持更完整的短期实验，但仍不足以证明年度规律与极端大促泛化能力。

### 9.2 实验记录必须能还原

至少保存以下内容：

- 目标列、单位、门店与SKU范围。
- 数据版本、提取时间、缺失和缺货处理方式。
- 每次预测的发出时间、目标日期和步长。
- 训练、验证、测试边界，重训规则和特征可得性。
- 模型设置、失败样本及失败后的回退规则。
- 逐条实际值与预测值，而不只是一个最终分数。
- 与基线比较的绝对改善量和相对改善比例。

例如基线MAE为4kg、候选为3kg，绝对改善为1kg，相对降低(4−3)÷4=25%。这不等于损耗减少25%，也不等于服务水平提高25%。从预测指标到业务收益还需要后续决策评估。

### 9.3 写出一段不夸大的实验结论

可参考以下格式，把括号内容替换成真实结果：

“本实验预测［门店与SKU范围］的［目标与单位］，在［发出时间］生成未来［步长］预测。使用［时间区间］进行验证，锁定方案后在［测试区间］评价。相较［基线］，候选方法的［指标］从［数值］变为［数值］。改善主要发生在［分组］，但［其他分组或场景］仍有不足。结果仅支持当前样本与协议下的结论，下一步需要验证［具体未覆盖条件］。”

这个模板中的“测试区间”必须注明是否事先未暴露。如果使用已看过的第141至180天，应改写为“在历史已暴露区间复核”，并说明哪些模型选择发生在查看结果之后。不能仅凭使用了“测试”一词，就把开发过程中的比较包装成独立证据。

如果结果没有超过基线，也是一份合格结论。它帮助你排除无效复杂度，或者发现缺失的业务信息。不能为了“模型升级”的叙事而只挑选表现好的SKU发表。

### 9.4 禾味与服装案例怎样迁移

禾味的关键限制包括生鲜保质期、短采购周期、菜品与食材BOM、净耗用与损耗口径。匿名服装企业更可能面对款色码稀疏、断码、新品无历史、长交期和生命周期。学习过的回测原则仍然适用，但目标粒度、预测范围和可用基线会改变。

例如服装采购提前8周，不应只展示次日预测很准；款色码每天大部分为0，也不应只用全公司WAPE掩盖小SKU表现。可以先在款式或品类层级学习较稳定的规律，再研究怎样分配到颜色与尺码，但不能假定各层预测自然相加一致。

下一阶段再进入全局模型、树模型、间歇需求、层级协调、新品预测和概率预测。判断是否需要升级的依据，应是现有方法遇到的具体问题，而不是算法名称看起来更先进。

## 基础部分自测清单

完成这部分后，应能在不查公式的情况下回答：

1. 我到底预测销量、潜在需求、净耗用还是采购量？
2. 一个特征与一个参数有什么区别？
