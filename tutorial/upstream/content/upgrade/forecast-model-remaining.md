## model-causal-three：三商品全式与混杂识别

### 1. 业务问题与单位

同一品类三个商品A、B、C，基准日需求分别100、80、60件，基准售价分别10、12、8元/件。A提价可能把客人推给B，也可能使搭配购买的C减少。预测对象是潜在需求均值，不是已经被库存上限截掉的销量。当前小实验没有缺货删失，observed_sales等于latent_demand；若把stockout改成1，验证器拒绝直接拿这份销量估弹性。

每行一SKU一天；每个设计168天，共2×168×3＝1,008行。文件中的随机版 randomized 在每个8天区组内把三商品价格的高低组合全部覆盖，并用固定随机种子打乱顺序；隐藏需求冲击在区组内相同。它是有意平衡的外生价格教学试验，不是真实门店A/B实验。confounded版把A价与隐藏需求冲击关联，代表运营人员看到旺季信号后抬价。

先写含相对竞价的一般式：

```text
ln(Q_i / Q_i0)
 = α_i + β_ii ln(P_i / P_i0)
   + Σ_{j≠i} β_ij ln[(P_j / R) / (P_j0 / R0)]
   + γ_iᵀX + ε_i
```

逐符号解释：

- i是被预测的商品，j是其他商品。矩阵的行是需求商品，列是被改变价格的商品，不能转置着解读。
- Q_i是该期需求均值，Q_i0是可比基准需求，均为件。P_i、P_i0为当前和基准售价，均为元/件。比值无量纲，才可取自然对数ln。
- R是外部品类参考价，R0为它的基准值。本题固定R＝R0＝10元/件，所以相对竞价项化成ln(P_j/P_j0)。外部参考价必须在预测时点已可得。
- α_i是基准修正；β_ii为自价系数，β_ij为交叉系数。γ_iᵀX是每项控制变量与其系数相乘再相加，例如γ_promo×已公布促销标记。
- ε_i是没被模型解释的变化，不可以假装它一定与价格独立。
- 弹性是局部比例导数，不是“涨价1元”的绝对销量变化。β_ij＝0.35表示其他条件固定时，j价小幅增加1%，i需求约增加0.35%。大改价必须回到指数式。

本题结构系数表：

| 需求商品＼价格商品 | A价 | B价 | C价 |
|---|---:|---:|---:|
| A需求 | −1.40 | +0.35 | −0.15 |
| B需求 | +0.40 | −1.20 | −0.10 |
| C需求 | −0.20 | −0.15 | −0.90 |

A与B的正交叉项在这个模拟设定中代表替代；A/B与C的负项代表互补。品类总需求不守恒：价格可以让顾客离开整个品类，也可以带来新顾客。

### 2. 为什么类别均价会改变导数

若R并不是固定外部基准，而是R＝Σ_k w_kP_k，w固定且和为1，则：

```text
a_k = ∂ln R / ∂ln P_k = w_k P_k / R
∂ln Q_i / ∂ln P_k
 = β_ii·1{k=i} + Σ_{j≠i} β_ij·(1{j=k} − a_k)
```

1{条件}在条件成立时为1，否则为0。因为调整P_k同时改变共同分母R，所以β_ik通常不再单独等于纯交叉弹性。若权重也随销量变化，还要加入权重变化的导数。本实验固定外部R，避免把这个联动藏起来。

### 3. 一次联合价格情景，逐项代入

现在A从10变10.8，B保持12，C从8降到7.36。促销与隐藏冲击保持基准值0。对数变化：

```text
x_A = ln(10.8/10) = 0.0769610411
x_B = ln(12/12) = 0
x_C = ln(7.36/8) = −0.0833816089
```

A的每一项：−1.4×0.0769610411＋0.35×0−0.15×(−0.0833816089)＝−0.0952382162。因此Q_A＝100×exp(−0.0952382162)＝90.915633件。

B：0.4×0.0769610411−1.2×0−0.1×(−0.0833816089)＝0.0391225773，所以Q_B＝80×exp(0.0391225773)＝83.191836件。

C：−0.2×0.0769610411−0.15×0−0.9×(−0.0833816089)＝0.0596512398，所以Q_C＝60×exp(0.0596512398)＝63.687977件。

品类需求由240变为237.795446件，不能强行把三项缩放回240。程序使用随机版训练得到的价格系数和单独给定的基准需求做这次相对变化预测；并非用混杂版斜率改价。由于这个理想平衡模拟的价格系数恢复近乎精确，手算与程序相符。

若当前可售库存为[80,60,50]，无补货销量分别是min(Q,I)＝[80,60,50]。按一件取整的建议缺口为：

```text
G_i = max(0, ceil(Q_i) − I_i)
G = [11,24,14] 件
```

ceil向上取整。若单位成本为[6,7,4]元，无补货情景销售毛利为(10.8−6)×80＋(12−7)×60＋(7.36−4)×50＝852元；假设建议补货全部及时到货且需求实现，则销售毛利为1,066.345820元。这是售价减单位销售成本的毛利，未计尾货、运费、整箱、MOQ、采购现金流和报废，不是净利润，也不是批准采购。

### 4. 真实拟合与反号

数据生成机制是：

```text
ln(Q_i / Q_i0) = Σ_j β_ij x_j + 0.12·promo + 0.4·z
```

z是隐藏需求冲击，只存在于模拟真值。随机版价格高低组合与z在训练区组内正交。混杂版则令A的对数相对价x_A＝0.12z＋0.03s_A，其中s_A为−1/+1的价格扰动。旺需求时价格也高，于是省略z后把旺需求错误归因于提价。

训练仅使用day 0–111；day112–139留作验证，day140–167留作测试。此次“价格识别”验收只检查训练设计下能否恢复已知真值，不把留出时间块的存在当作已经完成真实因果验证。代码没有用这些留出标签选价格系数，也没有报告未经执行的样本外因果效果。

最小二乘不是手填答案。对每SKU构造设计矩阵的一行：[1,x_A,x_B,x_C,promo]，目标是一行ln(Q_i/Q_i0)，调用np.linalg.lstsq实际求解，使各行预测残差平方和最小。训练矩阵满秩才允许求解。输出系数顺序为[截距,A价,B价,C价,promo]。

实际输出：

- 随机版A自价系数约−1.400000，与真值一致；整个价格系数矩阵最大误差小于10⁻⁸。
- 混杂版忽略z时，A自价系数约+1.154101。不是“顾客更喜欢贵价”的证据。
- 仅教学诊断的oracle再加入z后，A自价系数回到−1.400000。真实业务中z通常拿不到；不能把该隐藏列塞进线上特征来宣布解决混杂。
- 随机版只随机化价格，不随机化promo。由于promo与隐藏冲击在这批训练区组里有关，拟合的promo系数约0.368，而生成真值为0.12。价格试验恢复成功不表示控制变量的所有系数也可解释为因果。

该数据无额外测量噪声，价格组合又特意平衡，近乎精确的恢复是教学验算优势，不是对真实数据精度的保证。现实还需识别缺货删失、同时促销、曝光差异、季节、反向因果、溢出、价格共同变化与实验单位干扰。仅多放一些控制列不能自动保证没有遗漏混杂。

### 5. 学员验收

1. 不运行模型，先把A的三个项逐项算完，再对照90.915633。
2. 检查“行需求、列价格”，独立解释β_BA与β_AB为何不是同一个数字。
3. 把price_A改成0、stockout改成1、price_available_at改到预测后：程序必须拒绝，不自动把0补成1。
4. 改成超出训练支持的价格20元：情景函数必须报外推错误。落在价格范围内也不是因果可用的充分条件。
5. 说明ln(Q)不接受零需求；log1p改变模型与弹性含义。遇到真实零需求应选适当的计数/零膨胀模型或分开建模，不偷偷删零。
6. 能说出混杂版反号、oracle限制，以及缺口不是订单。

## model-pricing-stochastic：三期随机动态定价

### 1. 不是先看到需求再选价格

生鲜还可卖3小时，现有5件。每期可选10或8元/件，只能降价不能再涨，最后每剩一件要付1元处理费，因此残值s＝−1元/件。第4期到期禁售，只处理剩余库存；没有跨期补货，也没有新鲜度不同的批次混卖。初始价格上限同时约束DP首期动作、固定价与预定价格序列；例如把initial_price_ceiling改为8且保持只降不升后，合法对照只剩8/8/8，不能继续拿10元路径充当可执行对照。

在每期开始时只知道库存和上一期价格，先选价，再看到本期高/低需求。两种需求情景各概率0.5，且在本例中各期独立：

| 期t | 价格p | 低需求 | 高需求 | 低/高概率 |
|---|---:|---:|---:|---|
| 1 | 10 | 1 | 3 | 0.5/0.5 |
| 1 | 8 | 2 | 4 | 0.5/0.5 |
| 2 | 10 | 1 | 2 | 0.5/0.5 |
| 2 | 8 | 2 | 4 | 0.5/0.5 |
| 3 | 10 | 0 | 1 | 0.5/0.5 |
| 3 | 8 | 1 | 3 | 0.5/0.5 |

低价需求响应更高是设定，非估计结论。库存只限制成交，不应直接把潜在需求改成库存。若一次需求大于库存，丢失需求不向后积压。

### 2. 每个符号都落在状态上

```text
S_t = min(I_t, D_t(p_t))
I_{t+1} = I_t − S_t
V_4(I, p_prev) = sI = −I
V_t(I,p_prev) = max_{p∈{8,10}, p≤p_prev}
  Σ_{ω∈{低,高}} π_{t,p,ω}
  [p·min(I,D_{t,p,ω})
    + V_{t+1}(I−min(I,D_{t,p,ω}), p)]
```

- t是当前期，I_t是该期开盘库存，单位件；p_t是先选的价格，单位元/件。
- D_t(p)是该价格下尚未发生的需求；ω是低/高情景，π为对应概率。
- S_t是真正成交件数，不能用D_t直接乘价而无视库存。
- V_t是从该期起到期末的最大期望“销售收入＋残值”，单位元。初始货物已经在手，模型没有采购成本决策，因此这里不叫完整净利润。
- p_prev记忆上一期价格，保证只降不升。若只把库存放进状态，会忘掉能否重新涨价的限制。
- max在期望求和外面，表示未知本期ω时必须选一个价格。把max放入每个情景内部会偷看未来。

### 3. 先算最后一期

第3期剩2件、上期价10元：

- 选10元：低情景售0剩2，值0−2＝−2；高情景售1剩1，值10−1＝9；期望0.5×(−2)＋0.5×9＝3.5。
- 选8元：低情景售1剩1，值8−1＝7；高情景售2剩0，值16；期望0.5×7＋0.5×16＝11.5。
- 因而V_3(2,10)＝11.5，选8元。不能写“平均需求2，卖2件赚16”，那会忽略低情景的库存尾数。

同理，V_3(0,10)＝0，V_3(1,10)＝8，V_3(3,10)＝15。若上一期已降至8，合法动作只剩8，仍按同一递推求值。

### 4. 再算第二期的两个关键库存

第二期有4件、上期10元：

```text
选10：0.5×[10×1 + V_3(3,10)]
     +0.5×[10×2 + V_3(2,10)]
     =0.5×25 +0.5×31.5 =28.25
选8 ：0.5×[8×2 + V_3(2,8)]
     +0.5×[8×4 + V_3(0,8)]
     =0.5×27.5 +0.5×32 =29.75
```

因此剩4件时降到8元，V_2(4,10)＝29.75。

第二期有2件、上期10元：

```text
选10：0.5×[10 + V_3(1,10)] +0.5×[20 + V_3(0,10)]
     =0.5×18 +0.5×20 =19
选8 ：两个情景都售2件，值16
```

因此剩2件时保持10元，V_2(2,10)＝19。这正是根据已观察到的库存调整价格，而不是事先写死一条折扣曲线。

### 5. 回到第一期

初始5件。若先选10元，低需求后剩4件，高需求后剩2件：

```text
0.5×[10 +29.75] +0.5×[30 +19] =44.375元
```

若先选8元，以后不能回升，只能继续8元，期望40元。故首期选10元。

程序输出的同一场景协议对照：

| 策略 | 期望收入＋残值 |
|---|---:|
| 固定10元，10/10/10 | 37.625 |
| 固定8元，8/8/8 | 40.000 |
| 事先写死10/8/8 | 42.875 |
| 事先写死10/10/8 | 43.625 |
| 观察库存后滚动选价 | 44.375 |

44.375只是在本题离散状态、两种价格、独立情景和给定约束下最优。相对最佳预定序列增加0.75元，来自第二期可根据第一期已经发生的销售分支选价；不是承诺上线就提高利润。

每条三期低/高路径概率为0.125，共8条，输出保存每期先选价格、再观察情景、成交和库存。独立测试将历史相同的路径合并检查，要求当前动作相同，防止预知未来。

### 6. 三价格、时间与库存响应表

price_response.csv另有42行：生鲜3小时×3价×2开盘库存＝18行，服装4周×3价×2开盘库存＝24行。

生鲜价为8/9/10。9元的每个情景需求由8与10的对应低/高需求线性插值；例如第一期为1.5/3.5件，均值2.5件。若库存2件，期望成交是[1.5＋2]/2＝1.75件，而min(2,2.5)＝2是错误的“先平均再截断”。DP本题仍只选择两端价格，不将这张扩展表冒充已求三价格最优。

服装价为60/80/100元，周期t＝1…4周，设定确定性需求D_t(p)＝(32−5t)×(100/p)^1.2；开盘库存20或80件，销量min(I,D)。例如第1周100元需求27件、库存20时成交20件；第4周100元需求12件。它展示季末基础需求下降与价格响应的联合变化，不是从四周数据估出季节曲线。服装到第5周在本表设为禁售，实际业务是否禁售、转仓或清算必须由合法政策决定。

两类业务都必须先确认可售期和最低价。把expiry_period改到3期会被当前三期验证器拒绝，不会悄悄继续销售；改变负残值会重新计算策略。单批次教具不覆盖多批次FEFO与食品安全判定。

### 7. 学员验收

先手算V_3(2,10)，再算V_2的2件和4件两状态，最后得到44.375。检查八路径概率和为1、库存非负、成交≤库存且≤需求、价格只降不升。将一行概率0.5改成0.6必须失败；将需求改为−1、缺一情景、重复情景也必须失败。初始库存0时价值应为0。剩余处理费增大时，重新求解，不拿旧动作表硬套。

## model-tree-trained：实际训练的全局梯度提升树

### 1. 这次真正做了什么

运行包使用scikit-learn的GradientBoostingRegressor训练全局回归模型，三个SKU共同参与。它是实际梯度提升树，不是四行手工分裂，也不是运行LightGBM/XGBoost/CatBoost的替代声称。没有这些库也能学懂相同的提升思想；各库性能、类别编码与工程实现不能混为一谈。

数据生成420天×3SKU。前14天用于历史暖启动，交付特征day14–419，共1,218行。目标是已定义营业日内的需求件数。每个营业日17:00结束，销量17:30已入账，18:00预测次日；促销、天气预报与已知交期均在当日12:00发布。这里的“天气”是昨日已经发布的预报快照，不是次日实测。

### 2. 每一列为什么合法

| 列 | 定义 | 预测时是否已知 |
|---|---|---|
| sku_A/B/C | 三个SKU的one-hot列，每行一列1其余0 | 静态已知 |
| lag1 | 上一个营业日已发生需求 | 昨日17:30可得 |

### 4. 从线性到树，逐符号看更新

线性Ridge解的是：

```text
min_{b,w} Σ_train (y_n − b − Σ_j w_j z_nj)^2 + λΣ_j w_j²
```

n为样本，j为特征，z为只按训练集均值与标准差缩放后的特征，b为截距，w_j为权重，λ＝1。截距通常不惩罚；本包使用sklearn的标准行为。标准化器从训练数据学习，不能先在全数据上fit。

平方损失梯度提升的教学更新为：

```text
F_0(x) = 训练标签均值
r_nm = y_n − F_{m−1}(x_n)
h_m = 用训练特征拟合残差r_m的一棵浅树
F_m(x) = F_{m−1}(x) + η·h_m(x)
```

m是第几棵树，η是学习率；本例η＝0.05、共120棵。每轮专门修正前一轮剩下的误差，并不是把120棵树互不相关地训练再平均。max_depth限制单棵树层数，min_samples_leaf＝12防止叶子只记少数点。固定random_state＝20261106。

一个叶子手算：四个训练残差[−2,−1,3,4]，若只用一个常数叶子，平方误差最小的输出是均值1；这四点的SSE为9＋4＋4＋9＝26。若某合法特征阈值把前两点和后两点分开，叶子输出分别−1.5和3.5，两叶总SSE＝0.25＋0.25＋0.25＋0.25＝1。损失下降25。若某样本当前预测20、落入输出3.5的叶子，本轮更新为20＋0.05×3.5＝20.175。此手算解释原理，不冒充运行模型某棵树的真实节点。

### 2. TFT与DeepAR各把这些块放在哪里

TFT是一类多步预测架构，可区分静态协变量、历史观测协变量和未来已知协变量，并用变量选择、门控、序列编码和注意力等结构组合。常见实现输出各期若干条件分位数。注意力权重或变量权重不是自动成立的因果解释。

DeepAR是一类自回归概率模型，把历史目标、动态协变量与静态商品信息输入循环网络，输出下一步分布的参数，再抽样滚动形成未来路径。连续值可用相应连续分布，计数需选适当计数分布；不能仅因为叫DeepAR就宣称一定输出负二项。训练时真实历史目标可以逐步喂入；多步预测时未知未来目标要用预测分布滚动，不能继续喂真实未来。

符号化写法：

```text
h_t = RNN(h_{t−1}, [scaled_y_{t−1}, dynamic_x_t, static_embedding])
θ_t = output_head(h_t)
y_t^(s) ~ p(y | θ_t)
```

h_t为隐藏状态，方括号表示拼接；θ_t为概率分布参数；s表示第几条模拟路径。此式描述数据流，不是本包已经执行过的训练。当前没有torch，未训练TFT/DeepAR，也不拿人工样本冒充它们的预测。

### 3. 5条模拟路径怎样变成P50/P90

第一商品第一天的5个样本为[8,9,10,11,12]件；第二天[7,8,9,10,11]，第三天[6,7,8,9,10]。程序按numpy.quantile的method="higher"计算：

- 第一商品P50＝[10,9,8]；P90＝[12,11,10]。
- 第二商品P50＝[20,19,18]；P90＝[24,23,22]。

“H​​igher”取相邻排序位置中较高的观测样本。5条路径非常少，P90在这里落到最大样本，并不证明90%覆盖已校准。逐期P90之和一般也不等于总需求P90；要算累计需求分位数，应先在同一条路径内加总，再对路径总量取分位数。这批路径人为同向，碰巧相等也不能推广。

|---|---|---|---|---:|---:|

| V2 | train | shirts | (0.8,0.2) | 1000 | 120 |

余弦相似度与权重：

```text
cos(u,v) = (u1v1 + u2v2) / [sqrt(u1²+u2²)·sqrt(v1²+v2²)]
w_j = max(cos(u,v_j),0) / Σ_{k∈选中邻居} max(cos(u,v_k),0)
r = Σ_j w_j·(销量_j / 曝光_j)
新品预测 = 计划曝光 × r × 趋势系数
```

先筛相同类别，取相似度为正的前2个历史款。cos是方向相似，不受向量整体倍数影响；欧氏距离则受尺度影响，所以不能把未经归一化的两种距离混着用。零向量模长为0，余弦未定义，程序明确拒绝。

对V7=(0.9,0.1)：模长sqrt(0.82)；V1模长1，点积0.9，所以cos(V7,V1)＝0.993883735。V2模长sqrt(0.68)，点积0.74，得到cos(V7,V2)＝0.990992430。两款归一化权重分别0.500728334和0.499271666。

基准转化率r＝0.500728334×0.1＋0.499271666×0.12＝0.109985433。两个已发生可比期间，曝光均6000，销量从500到550，因此趋势系数＝(550/6000)/(500/6000)＝1.1。两期都早于预测原点，不用留出款销售来倒算趋势。

V7预测＝1000×0.109985433×1.1＝120.983977件，事后实际118。V8同理得到87.983977件，事后实际87。这只是2款留出的教学误差，不足以证明视觉类比稳定有效。

若没有同类正相似邻居，代码回退到历史6款总销量/总曝光，再乘既定趋势；输出fallback=true。此回退把多个类别合并，只是透明保底，真实业务可选择人工复核而非自动首单。若向量、曝光分布、价格或上市渠道不具有可比性，应拒绝类比，不能只因cos高就认定需求相同。

另做一项真正执行的聚类实验：把6款历史向量先除以各自模长，再用sklearn KMeans拟合K＝2个簇，n_init＝10、random_state＝20261106、algorithm＝lloyd。代码在fit与predict内部用threadpoolctl固定单线程，调用者无需设置环境变量。目标为Σ_j ||v̂_j−μ_{z_j}||²，v̂_j为归一化向量，z_j为簇编号，μ为簇中心。算法交替“把点分给最近中心”与“用簇内点的均值更新中心”，新款只分配到已经拟合的中心，不参与重训。

## model-prophet-decomposition：讲清分量，不伪造运行

### 1. 模型形式

Prophet常用加性形式为：

```text
y(t) = g(t) + s(t) + h(t) + ε_t
```

g(t)为慢变化趋势，s(t)为周期项，h(t)为节假日/事件，ε_t为未解释误差。四项单位均为预测目标单位。若选择乘性季节性，形式与单位解释不同，不能把加性公式原封不动套上。

分段线性趋势可写成：

```text
g(t) = [k + a(t)ᵀδ]·t + [m + a(t)ᵀγ]
γ_j = −s_jδ_j
```

k为初始斜率，m为初始截距，s_j为第j个候选变点时刻；a_j(t)在t到达s_j后为1，否则0；δ_j改变斜率，γ_j补偿截距使曲线在变点连续。用稀疏/收缩先验约束过多变点是模型思想的一部分。本教具没有拟合变点，不拿手工折线冒充估计结果。容量约束的logistic趋势是另一种选项，需要有效cap等输入；也未运行。

周期项通常用傅里叶基：

```text
s(t) = Σ_{n=1}^N [a_n cos(2πnt/P) + b_n sin(2πnt/P)]
```

P为周期长度，t与P必须同单位；N为谐波数，n为第n阶，a_n/b_n为待拟合系数。N大更灵活，也更容易过拟合。节日项可写h(t)＝Σ_l κ_l·1{t属于事件l的窗口}，κ_l是该窗口的效果，预测时必须知道窗口，而不是根据销量峰值事后补“节日”。

### 2. 14行算术示例

prophet_components.csv给14天明确设定的分量：g(t)＝100＋2t，s(t)＝10sin(2πt/7)，第7天h(t)＝20，其他天0。因为这些系数是手工给定，所以输出是分解算术，不是Prophet预测。

- 第1天：趋势102，周项约7.818315，节日0，总和109.818315。
- 第7天：趋势114，周项0，节日20，总和134。
- 第14天：趋势128，周项0，节日0，总和128。

14天只能展示两个完整的7天周期，不能据此声称识别年度季节性；也不能仅凭这张表估计可靠的节日效果和预测区间。

### 3. 与ETS、ARIMA、Croston/TSB放在同一比较台

| 方法 | 主要建模对象 | 本课需避免的误解 |
|---|---|---|
| ETS | 随时间递推的水平、趋势、季节状态 | 不是只能处理完全不变的均值 |
| ARIMA/SARIMA | 差分后序列与误差的滞后依赖 | 加入差分并不自动解决价格或政策因果变化 |
| Prophet | 趋势、周期基函数、已知事件等结构分解 | 不是“自动适用于所有季节”的黑箱；没有足够周期就无法可靠识别 |
| Croston/TSB | 间歇非零需求的大小、间隔或发生概率 | 不能把每日平滑预测误当每一天都会成交 |

统一回测接口应接受：已到达的训练表、forecast_origin、horizon、在原点已知的未来协变量，返回[sku,target_date,origin,model,prediction,optional_quantiles]。每个滚动原点只用该时点之前的数据重新fit或按预先固定规则更新；节日、预报、价格版本同样受available_at约束。对所有模型使用相同目标、原点、预测期、样本和指标，调参仅在训练/验证区段。

当前未安装Prophet，因此没有执行Prophet.fit、没有对它报告WAPE或区间覆盖、没有把上面的算术输出与已训练GBDT公平排名。真正加入对照需要安装兼容依赖、验证数据接口和模型收敛，并重新按同一回测协议运行；本课只闭合解释与算术层。
