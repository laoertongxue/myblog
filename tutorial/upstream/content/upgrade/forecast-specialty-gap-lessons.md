# 八项专项缺口的分阶段教程与模拟项目

这组补课回答五个具体问题：未发货订单今天还会取消多少；等满24小时以后该裁多少；退货预测为什么不能直接拿去向客户承诺；COD高风险单如何进入有限人审；有部分到货的PO还要等多久。读者只需会比例、乘方、平方根、坐标图和简单方程。先用小数手算，再看模型，再运行项目。每处“最优”都只针对写出的玩具成本、容量和概率假设。

所有商品、订单、顾客、供应商、仓库和事件均为虚构模拟。项目不连生产系统，不给真实订单挂起，不联系客户，不下采购单或裁剪工单。模拟数据上的拟合、流程通过和业务效果是三种不同证据，不能混称“上线验证”。本补课对应P14、P15、R01、R04、D01、D02、L02、L03；不改写其他白皮书条目的覆盖结论。

## 开始之前 运行顺序与共同时间规则

项目目录是 forecast-specialty-gap-labs。需要Python、numpy、pandas、scipy和scikit-learn；确切实跑版本在包内requirements.txt。这里确实训练了scikit-learn逻辑回归与GBDT，没有安装或运行LightGBM、lifelines、AFT、深度网络或实时服务。缺依赖时程序会报缺少哪个包，不能把“给了源码”说成“在你的电脑上跑过”。无需联网取数据。

运行顺序：

```bash
python run_all.py
python -m unittest discover -s tests -v
```

第一条生成原始CSV，再从这些CSV读取数据、建标签、训练和写结果；会覆盖包内同名数据和结果。第二条测试时间边界、计数守恒和流程。修改原始输入后运行以下命令才会保留修改：

```bash
python run_all.py --reuse-inputs
```

六个受保护的原始输入为hazard_orders.csv、hazard_events.csv、return_order_cohorts.csv、cod_orders.csv、po_release_features.csv、po_receipt_events.csv。其余person-day、快照和输出是重建结果，手改会被覆盖。--reuse-inputs不是生产数据适配器：它仍要求本项目字段、事件类型、数值范围和完整模拟历史。空类别、单一标签、全无成熟样本等会失败，应报告不足并停止，不可补造标签。对真实未完成PO，不能强行提供未来完成事件满足模拟输入契约。

所有day都是各项目自己的整数日历。day=10表示项目起点后第10天，不是统一业务日期。as-of表示“站在那个时刻，仅允许看到当时已经发生或已公布的东西”。训练、选参数、最终评估用不同时间块；验证集只选参数，测试集不负责选参数。同一订单的多行必须留在同一块。行数多不等于独立订单多。

学习可分三遍：第一遍完成每章手算；第二遍运行并核对CSV；第三遍做改参数/破坏边界练习。模型表现不好也是结果，不能为了通过验收更换测试集。

## 模块 SG01 从订单展开为年龄hazard的实际拟合

对应P14。目标是得到“这张订单已经等到第a天且尚未取消、尚未发货时，接下来这一天取消的概率”。不是“下单以来总取消概率”，更不是“所有年龄订单一起算一个比例”。

### 第一步 一单多行与风险集

person-day直译为“一个人一天”，这里是一张订单一个等待日。订单A在第3天取消，应写三行：(A,1,0)、(A,2,0)、(A,3,1)。最后一个数字y取0表示当天未取消，取1表示当天取消。第4天不能再写A。订单B在第2天结束时发货，写(B,1,0)、(B,2,0)，之后停止。订单C观察只到第2天，也写两行0，但原因是观察截止，不是已经永不取消。

本项目约定：每天先观察取消，日末发货；同一天两种潜在事件时取消优先。风险集包括该天开始时仍等待的订单。现实事件若只有日粒度且先后不清，必须先制定并做敏感性分析，不能悄悄套本规则。

小例子：某日开始有10张未发货未取消订单，当日取消2张，则当天经验hazard=2÷10=0.2。第二日只有8张还在等，若又取消1张，当天hazard=1÷8=0.125。它不是1÷10。到第二日末仍等待的比例=(1−0.2)×(1−0.125)=0.7，累计取消比例=1−0.7=0.3。

“发货停止继续观察”叫删失。它与取消不是同一个标签。只有当发货选择与潜在取消在已知条件下足够独立，才可把拟合的等待hazard用于假设继续等待的情景。本模拟刻意让发货时机在给定仓库后独立于潜在取消。现实中高价值顾客优先发货，可能还存在未记录的VIP信息；加入价格和仓库不能证明这种偏差已经消失。

### 第二步 逐个拆开年龄哑变量与logit

模型写成：

z = b₀ + b₂I(a=2) + b₃I(a=3) + … + b₁₂I(a=12) + β₁x₁ + β₂x₂ + β₃x₃

h = 1 ÷ (1 + exp(−z))

- a是等待年龄，单位“天”；本项目只训练第1至12天。
- I(a=2)是开关：a等于2就取1，否则取0。其余年龄开关相同。
- 第1天没有自己的开关，全部年龄开关为0时，b₀就是第1天的基础分数。少放一个开关是为了避免“截距加所有开关”重复表达同一个量。
- x₁=price÷100，例如120元写成1.2，不是120；β₁是每100元价格对应的分数变化。
- x₂是虚构仓库0/1，x₃是是否促销0/1。0和1在本模拟确实是二分类，不可把仓库编号8误当成仓库编号1的八倍。
- b和β是训练找出的数，不是人为写好的概率。z可以正也可以负。
- exp(u)表示自然常数e约2.718的u次方。exp(0)=1，所以z=0时h=1÷2=0.5；z越大，h越大，且始终在0到1之间。

logit(h)=ln[h÷(1−h)]是上式的反变换。ln是以e为底的对数。h=0.25时，h÷(1−h)=1÷3，ln(1÷3)≈−1.0986。把z=−1.0986放回第二式，得到h≈0.25。本模型叫离散时间logistic hazard；虽然有年龄基础项和订单特征，仍不能因此叫Cox模型。

手算练习用一组自设系数，不是本次训练成绩：b₀=−2，某一天龄开关项=0.3，β₁=0.2且x₁=1.2，β₂=0.4且仓库=1，促销项=0。先算z=−2+0.3+0.2×1.2+0.4=−1.06；再算h=1÷(1+exp(1.06))≈0.2573。不能把四项概率直接相加。

### 第三步 拟合到底在做什么

每行真实答案y只有0或1，模型给h。若实际取消y=1，给它0.8比给0.1更合理；若未取消y=0，给0.1比给0.8更合理。对数损失逐行写为：

loss = −[y×ln(h) + (1−y)×ln(1−h)]。

y=1、h=0.8时，loss=−ln(0.8)≈0.2231；y=1、h=0.1时，loss≈2.3026。小才好。程序反复调整系数，让训练行平均损失加系数惩罚更小。C越小表示惩罚越强，不表示概率越小。验证集在C=0.1、1、10中选一个，测试集只打一次分。

程序先标准化数值再训练：标准分=(原数−训练均值)÷训练标准差。只能用训练均值和标准差，不能先用全数据计算。outputs/hazard_coefficients.csv已把系数还原到原始特征单位，读者可以直接按“价格÷100、仓库0/1、促销0/1、年龄开关”复算，不必再重复标准化。

Brier分数是平均(h−y)²。一个取消样本的h=0.8，误差平方=(0.8−1)²=0.04；一个未取消样本的h=0.8，误差平方=0.64。所有行平均越小越好。这里它评估的是“被观察到的风险日”，不是证明未发货反事实曲线正确。

### 第四步 真实项目输入与验收

输入hazard_orders.csv有id、day、price、warehouse、promo；hazard_events.csv有订单id、事件日和cancel/ship。程序只从订单特征和已发生事件构造person-day，不从潜在真值建特征。

训练订单日0至99，观察到112；验证订单日120至159，观察到172；测试订单日180至219，观察到232。中间留间隔，保证12天标签已经走完。训练、验证、测试分别是2000、800、800张订单；person-day数分别为11777、4702、4852。原始表另有未用于这三个块的订单，不可把4800都称训练样本。

检查四件事：每单最多一行y=1；取消后没有行；各块id不交叉；known_at不晚于当天开始。默认结果选择C=1，测试Brier约0.07366；只用年龄的基线约0.07439，改善很小，不能用“显著领先”描述。hazard_age_calibration.csv把年龄逐行的平均预测与实际取消比例并列。

### 第五步 条件留存与边界练习

设S(a)是在约定继续等待且不发货、相应删失条件成立的情景中，到第a天仍未取消的留存概率。它不是现实中同时受到发货退出影响的“还在等待订单占原始订单的比例”。已知订单已经活到a天，再等L天的留存概率是S(a+L)÷S(a)，也等于从第a+1到a+L天的(1−hazard)相乘。历史已经取消的订单不能再扣第二遍。

例如前面第一天留存0.8，后两天hazard为0.1、0.25，则S(3)=0.8×0.9×0.75=0.54。对当前已经过第一天的80单，用0.54÷0.8=0.675，预计剩54单。错用80×0.54只得到43.2，是重复扣了第一天的取消。

练习：把某个事件改到订单创建前，再运行--reuse-inputs，应明确失败；把价格提高100元，复算z变化是否恰为β₁。第13天及以后没有支持，函数拒绝超范围，不能把第12天hazard无限外推。本补课不推断消费者因果耐心，不证明删失独立，不把同一订单的多行当独立样本计算显著性。

## 模块 SG02 24小时静默 交期混合与受约束的裁剪和超卖

对应P15。目标是把上一章的概率变成可以检查的建议，而不是把“预计净需求”直接当裁剪量或允许卖出的件数。任何真的锁单、裁剪、采购、超卖都不在本项目执行范围内。

### 第一步 先画出决策时刻

在订单年龄小于24小时期间，静默闸门只输出不进入不可逆裁剪建议；等于24小时才通过。23.999小时不通过，24小时通过。闸门测试不代表实际系统已拦住工单。

本例站在T+24h：现在已知仍等待80张同质、每张1件的订单。此前到底下了多少单不参与再次扣减。比较“现在裁固定q件”与“等到较晚时段裁固定q件”；两种政策都在此刻决定q，等待政策没有偷看未来真实需求。因此本题不是等待获得信息的价值，也没有声称找到了最优动态排产。

### 第二步 交期不确定时不能只看平均天数

交期L取3、5、8天，概率w分别为0.3、0.5、0.2，加起来恰为1。每种交期从第1天开始用条件留存pₗ=S(1+L)÷S(1)。对于80单，交期情景的期望净需求为80pₗ。

总期望净需求 = 0.3×80p₃ + 0.5×80p₅ + 0.2×80p₈。

“期望”是按可能性加权平均，不是保证到时恰好这个数。本次三个p来自实际拟合模型，约为0.86373、0.81292、0.75476，对应69.10、65.03、60.38件，加权约65.32件。平均交期=0.3×3+0.5×5+0.2×8=5天，但p在交期上不一定是直线，所以80p₅不一定等于65.32。

如果订单条件独立且同质，留下的订单数D服从二项分布：D~Binomial(N,pₗ)。N是当前活跃承诺数，D取0到N的整数。比如N=2且p=0.8，则D=0概率0.2²=0.04，D=1概率2×0.8×0.2=0.32，D=2概率0.8²=0.64。三种交期分别有一套分布，再按w混合。共同舆情或统一延期可能让订单一起取消，此时独立二项假设会低估尾部风险。

### 第三步 BOM与产能先限定可选动作

每件成衣要2米布和1套辅料，现有布160米、辅料90套、缝制容量85件。三种上限分别是160÷2=80、90÷1=90、85，因此最多min(80,90,85)=80件。min表示取最小值。不能因为辅料够90件就按90件裁剪，也不能先取65.32件再忽略整数和材料。

现在裁每件成本10元；晚裁每件12元，晚班只能做55件。多做一件承担8元净余货成本，少一件承担45元缺货成本。这里的余货成本是已扣除可回收价值的额外处理负担，10或12元加工材料成本仍单独计算，避免模糊地把同一笔成本算两次。

对于给定q和真实需求D：

成本 C(q,D) = c×q + 8×max(q−D,0) + 45×max(D−q,0)。

c是本政策每件成本，q是提前决定的数量；max(x,0)把负数改成0。例如现在裁q=68，最终D=65：成本=10×68+8×3+45×0=704元。若D=72，成本=680+0+45×4=860元。

期望成本把每个D的成本乘以其概率再相加。程序对现在裁q=0至80、晚裁q=0至55逐个枚举，不靠高深求解器。presale_hedge_cost_grid.csv包含每个候选的成本、容量、缺货概率。无服务约束的成本最低是现在裁68件，约740.51元；晚裁55件，约1126.26元。这里只是在给定例子里现在裁较便宜，不能推断所有预售都该立即裁。

### 第四步 低成本与可靠履约是两道门

不能把上面裁68件的低成本结果与另一套78件供应保证拼接成同一个“最优方案”。本项目为每个q同时算缺货风险。交期3、5、8天时可按期交付容量分别为78、76、72件；实际可交付为min(q,该情景容量)。

约束写作：每种交期情景下，P[D>min(q,容量)]≤0.05。P表示概率；“≤0.05”表示缺货概率不能超过5%。这不是“最多少5%件数”，两者不同。

在80单基础上裁68件，最坏情景缺货概率约59.21%，所以虽然成本最低，根本不满足5%服务约束。为当前80单挑最低成本且满足每种情景约束的q，得到74件，期望成本约810.20元、最坏情景缺货概率约3.045%。晚裁最大55件，当前假设下没有可行解，应显示不可行，不可悄悄放宽阈值或补上未授权加班。

动态超卖再枚举活跃承诺N=80至120，并要求找到不超过80件材料容量的供应承诺q。输出给出每个N所需的最小q。默认最多可支持85张活跃承诺，并必须承诺78件供应；它不是“裁68件却卖85件”。新增加的订单在此例中被假定与现有订单有同样年龄、特征和留存概率。现实新单刚创建，不能套用已经过24小时的老单留存，必须按各自年龄重新建分布。

### 第五步 验收与扩展

检查presale_silent_gate.csv四个边界；检查BOM容量80；检查成本最低与服务约束最佳分开；检查所有风险概率在0至1；增加N时缺货风险不下降；检查被选超卖量对应供应q在容量以内。把5%改成1%、布从160米降为140米，重新生成自己的场景，不沿用默认答案。planning(h, fabric_meters=140)得到容量70，现有80单已经没有满足5%约束的方案，必须返回无解、空供应承诺和空最大订单数，不能把仅通过交付容量的订单数标成可行，更不能转换空值导致程序崩溃。0米场景连晚裁也只能做0件。

本题给出的是单SKU、单层BOM、离散交期、固定数量的完整教学链；没有替代料、跨车间共享产能、加急、客户分层、等待后再优化或通用MRP/APS。概率校准错了，风险约束的5%也会错。生产推广必须另做数据审查、离线回放和人工审批。

## 模块 SG03 退货GBDT 时滞回流与ATP采购分账

对应R01、R04。一个订单“会不会退”与“一件退货哪天成为可售库存”是两道问题。退货申请、快递在途、仓库签收、质检合格、重新上架也不是同一状态。

### 第一步 给成熟标签一个明确期限

本例每行是一张一件订单。预测目标return30=1表示发货后30天内发生退货，0表示窗口结束仍未退货。刚发货三天还没退货不能立即标0。数据额外保留label_known_day=ship_day+30；训练期最晚发货99日，因此最晚129日才成熟。训练1400行，验证560行，测试560行，分别来自发货日0至99、140至179、220至259。

所有特征均在发货前或发货时可得：category品类0/1、size_mismatch尺码不合倾向0/1/2、live_channel直播渠道0/1、price100价格百元单位、promo促销0/1、history_rate当时已有历史退货率。尺码倾向在模拟中是事先可知特征，不是把这张订单退货后的原因抄回来。用户历史只用当前订单之前已经成熟的记录，不能包含自己的未来退货。

### 第二步 GBDT如何把多个特征变成概率

GBDT是一串逐步纠错的小树。树可以先问“是否直播”，再问“是否促销”，把满足不同条件的订单送进不同叶子。叶子贡献的是分数修正，不是最终概率。设第m轮分数为Fₘ，上一轮分数为Fₘ₋₁，小树输出为gₘ，学习率η控制每次走多大一步：

Fₘ(x)=Fₘ₋₁(x)+ηgₘ(x)，p(x)=1÷[1+exp(−Fₘ(x))]。

x是这一订单的特征集合；m数第几棵树；η本项目取0.05。以一条订单为手算例，初始分数F=0，对应p=0.5，真实y=1。此时“还差多少”的方向为y−p=0.5。若一棵教学小树输出0.5，取η=0.1，则新分数0+0.1×0.5=0.05，新概率约0.5125。真正程序会同时看全部训练样本，叶子还需优化，不是每个样本独立加自己的误差。

本项目实际训练GradientBoostingClassifier，100棵树，学习率0.05，叶子至少25行，在验证集比较深度1、2、3。深度是树向下最多分几层，不是特征个数。验证选深度2；测试Brier约0.20898，训练总体均值基线约0.23654。模型比基线好只针对本合成机制，不是企业退货率或商业收益证明。

### 第三步 乘退货概率之后还要乘良率与时滞

对第i件新发货商品：

未来第k天预计可售回流 Eᵢ(k)=pᵢ×γᵢ×dᵢ(k)。

pᵢ是30天退货概率；γᵢ是“确实退货后最终合格可售”的概率；dᵢ(k)是“最终合格可售的退货中，发货后第k天上架”的比例。d加总为1。这里d明确以最终合格品为条件，因此再乘γ一次恰当，不能把已经含不合格概率的时滞再乘一次良率。

手算：100件，p=0.3，γ=0.8；合格退货中第7天上架占0.6，第10天占0.4。预计第7天=100×0.3×0.8×0.6=14.4件；第10天=9.6件；合计24件。小数是重复实验的平均，不是仓库真收到0.4件。良率不是退货率，0.8也不能让所有已发货100件中的80件被算作退回。

本项目按品类从成熟训练退货估γ，再从该品类实际合格退货估d；对100件新批次逐件用GBDT预测p，再相加。100件的新批次只是借用了测试表的特征模板，真实标签不用于新批次预测。默认预计30天合格回流29.4681件，且所有本模拟合格回流最晚14天；现实可能更久，不能照搬14天窗口。

多个发货日的卷积只是“把每批次移到对应日再加起来”：日t发的货若滞后k天，进入t+k日那一格。例如日0的14.4件落在日7，日1同样发货的14.4件落在日8，不可都放进日7。本补课用一个新批次展示模型输出；原专项的多批次/当前退运状态回流继续适用，二者不要重复加同一订单。

### 第四步 三本账放在同一张纸上

第一本是实物可售账，只认实际质检通过且已上架：期末=期初+实际入库−实际发出。退货申请和预计回流都不增加实物库存。项目七天流水从40开始，实际合格上架共10、实际PO入库20、实际发出35，最后40+10+20−35=35件。

第二本是到期可承诺账ATP。本例只讨论同一个到期日14，初始已质检可售40件、到期前确定到货20件、已有订单占用35件：

严格ATP=40+20−35=25件。

因此一个新增30件请求，在本离线例中最多分配25件，剩5件不能因为“预计退回29.47件”就默认为已承诺。20件确定到货也需符合企业对供应确定性与时间的政策；若不能当硬供应，ATP应更低。真实多日期ATP还要逐期保证每个承诺日的可用量，不能拿第14天的货承诺第2天交付。

第三本是预测采购建议。未来总需求目标100件已经包含那35件被占用订单，不能再加35；安全缓冲10件：

不计回流建议Q₀=max(0,向上取整[100+10−40−20])=50。

计期望回流建议Q₁=max(0,向上取整[100+10−40−20−29.4681])=21。

向上取整表示20.5319件改为21件。Q₁是风险较高的计划方案，不保证供应充足，也不改变严格ATP=25。要真正形成风险保证，需要退货量/时点联合分布、保守分位数、供应可靠性和服务水平约束；本例不把“扣了均值”包装成稳健优化。

### 第五步 验收与反例

return_atp_procurement_comparison.csv同列显示虚拟回流、严格ATP、两个采购建议；return_physical_ledger.csv独立核对真实库存。验收要求预计合格回流不超过100件，按日之和等于按品类之和，γ在0至1，ATP恰25，实际账期末恰35。把γ手算改成0，应令虚拟回流为0、采购建议回到50，但既有实物账不能回退，因为已上架的真货不能因模型变动被抹掉。

如果商品法规或卫生条件禁止二次销售，γ=0；不能为了降低采购量继续套服饰良率。退货分布变了、促销渠道变了、质检积压变了，都需要重新校准。本项目不是完整逆向仓储系统，不自动退钱、不生成采购订单，也不允许把预计库存当硬ATP。

## 模块 SG04 COD订单风险与有限人审状态机

对应D01、D02。目标是预测拒收风险并展示一条不会绕过人审的离线流程。风险高不等于欺诈，不等于应取消。历史地区差异也不是对某类人的价值判断。

### 第一步 把实时要求拆成可检查的输入契约

COD是货到付款。模型使用address_complete地址是否完整、night_2_5下单是否在2至5时、pieces件数、basket100客单百元、history_sign_rate历史签收率、prior_orders既往次数、remote_region模拟偏远区域0/1。实际地址、手机号不进入本项目，所有实体匿名虚构。

历史率用平滑：(历史签收数+1)÷(历史单数+2)。新顾客历史0单得到1÷2=0.5，不能误写成0%签收。历史8单签收6单，则(6+1)÷(8+2)=0.7。它只是本教学基线，不代表正确的全公司先验。历史记录必须在评分时已知，history_known_at>score_time时函数直接拒绝。

score_cod(model,features,score_time,history_known_at,calibration_offset)是本地函数，检查缺字段、非有限特征、非有限时点和未来历史，再加上同一个已冻结校准偏移返回概率。批量评分与这一路径必须一致，不能在线返回原始概率却用校准后阈值。一次本地函数耗时不等于网络服务SLA：没有API网关、消息总线、鉴权、重试、并发、特征存储或线上可用性验证。教程把“实时评分需要什么输入”做成可运行契约，没有假装部署实时服务。

### 第二步 训练 校准 选阈值用四块时间

实际训练逻辑回归，2000单训练；400单校准；400单选择阈值；800单测试。训练日0至99，最晚109日标签成熟；校准120至139，最晚149日成熟；选阈值160至179，最晚189日成熟；测试200至239，最晚249日成熟。每一步的标签全部可用后，才进入下一块的评分时点。cod_fit_timeline.csv列出这条时间线；旧的“校准到139日却从140日选阈值”会被拒绝，因为139日订单要到149日才有标签。label_known_at被改为999也必须拒绝，不能只检查历史特征。

逻辑回归分数与第一章同形式，最终用sigmoid压到0至1。校准阶段只调整一个截距：原分数z，加校准偏移δ，得到p=1÷[1+exp(−z−δ)]。δ来自校准块，不能用最终测试答案。默认δ约0.05，不是把概率统一加5个百分点。

本次测试Brier约0.12875，均值基线约0.14037。它证明本合成数据里排序/概率预测有一些价值，不能证明人工复核会减少拒收。

### 第三步 阈值必须同时考虑容量

玩具假设拒收损失100元，每次复核5元，复核能把拒收概率相对降低30%。这一“30%”是显式假设，不是实验估出的处理效应。对风险p的一单，不复核期望损失100p；复核期望损失5+100p×(1−0.3)。当复核更划算：

5+70p<100p → 5<30p → p>1÷6≈0.1667。

但每日只能复核3单，不能给全体p>0.1667的人都派工。程序在验证块比较0.2至0.8的七个阈值；超过阈值后，每天只取风险最高的3单。默认阈值0.2，测试中210单被标高风险，只有116单被容量选中，二者不能混报。

白皮书举p>0.6是业务规则例子，不是普适最优阈值。项目CSV包含0.6候选，可直接比较规模。即使本例0.2成本较低，只要30%改善假设不成立，推荐也可能反过来。可把改善率做0%、10%、30%、50%敏感性表，但不得称为真实A/B收益。

### 第四步 状态机让每一步有出处

状态机就是“现在在哪一格，收到什么事件，允许走到哪一格”。离线样例定义如下：

- SCORED评分结束：低风险进入RELEASED放行候选；高风险进入HOLD挂起候选。
- HOLD有复核容量进入REVIEWING；没有容量进入REVIEW_QUEUED排队。
- REVIEWING收到顾客确认进入CONFIRMED；还需带审核员编号的reviewer_approved，才到RELEASED。
- REVIEWING收到顾客否认进入CANCEL_RECOMMENDATION取消建议，不执行真实取消。
- HOLD、REVIEWING、REVIEW_QUEUED超时统一进入EXPIRED_REVIEW待补审，不自动放行。
- EXPIRED_REVIEW只有带审核员编号的批准才进入RELEASED；没有编号就拒绝。

五个固定案例A至E分别展示确认放行、否认建议、排队超时、低风险、超时后人工批准。cod_state_machine_trace.csv记录前状态、事件、审核员、后状态。重复给已经RELEASED的订单发批准事件会拒绝，避免重复动作被误当成合法下一步。这里没有真正的工单ID分配、持久化锁或跨系统幂等保证，不能把这个纯函数说成生产工单平台。

“顾客确认了”不是“之后签收了”。人审反馈只能更新流程状态；拒收模型标签仍要等真正配送结果成熟。如果把“审核员放行”当签收标签，模型将学习历史审核员的选择，而不是用户实际签收。

### 第五步 如何验证而不夸大因果

结构验收：未来历史和缺字段必须拒绝；一天最多3单；超时绝不能直接RELEASED；无审核员不能批准；用户否认只能产生取消建议；重复非法转移要报错。53项测试中的这些检验能说明代码遵守了样例规则，不能说明人审有效。

若将来要估计人审因果效果，需要额外批准后的随机试验：在预先确定且容量容许的同类合格订单中随机分配“邀请复核”或常规处理，事先固定主要指标为成熟后的拒收/成本，记录分组、邀请、回应、实际处理和完整随访；按最初分组做意向治疗比较。不能只比较“接受复核的人”与“没回应的人”，因为两群可能本来就不同。需防止重复顾客跨组污染，并制定超时与服务安全规则。本项目只交付试验设计，没有执行试验、联系用户或声称识别处理效果。

## 模块 SG05 交期波动敏感性 未完成PO与分位数预测

对应L02、L03。这里分别回答“交期波动如何放大安全库存”和“这一张已经部分到货的PO下一次、最终还要多久”。PO是采购订单；本项目每张100件，分30、30、40三次到货。

### 第一步 先把安全库存公式每个量写清

SS=z×√[L̄×σD² + D̄²×σL²]。

- D̄是日均需求，单位件/天；σD是每日需求标准差，单位件。
- L̄是平均等待天数，σL是等待天数标准差。
- σ²表示标准差平方，也叫方差；两项放在同一时间计数约定下得到交期内总需求方差，单位件²。
- √是平方根，把件²还原为件；z=1.65是约95%单侧正态分位数近似，不是任意分布都能保证95%的常数。
- SS是额外安全库存，不是平均交期内总需求。补货点常还要加D̄L̄，并考虑现有在途与政策。

从容易的一组数开始：D̄=10、σD=2、L̄=4、σL=1。需求波动项A=4×2²=16；交期波动项B=10²×1²=100；总方差V=16+100=116；标准差√116≈10.7703；SS=1.65×10.7703≈17.7710，整件向上取18。B的占比=100÷116≈86.21%，A占13.79%。

这个加法来自条件拆分：若交期固定L天，每天需求独立且方差σD²，总需求方差为LσD²；交期本身变化时，平均需求D̄乘等待天数又增加D̄²σL²。在日需求独立同分布、交期与需求独立等条件下两项相加。需求与交期正相关、节假日、断货压低观测需求、批次相关，都可能使公式不适用。

### 第二步 改一个参数 看哪一项变了

把日均需求从10变20，保持其余不变：A仍16，B=20²×1²=400，V=416，SS≈33.65件，整件34。均值翻倍，交期波动项翻四倍，但SS没有机械翻四倍，因为最后还要开平方。

把σL从1降至0.5，D̄仍10：B=100×0.25=25，V=41，SS≈10.56件，整件11。交期标准差减半，交期方差项变为四分之一。若σL=0，B=0，SS=1.65√16=6.6件，整件7；这不意味着无需库存，只是不用覆盖交期波动，仍有日需求波动。

lead_variance_sensitivity.csv完整列出D̄=10、20、40和σL=0、0.5、1、2的12种组合，包含A、B、占比、连续SS与向上取整SS。验收既要看结果，也要看单位和保持不变的参数。这里固定σD=2，所以销量增大时相对需求波动下降；若真实σD也随均值上升，应一起改，不能选择性夸大交期影响。

### 第三步 只看完成PO为什么危险

某日看两张PO：A第8天收齐，B已经等20天仍未收齐。只看A会说平均交期8天；把B写成20天收齐也错。B提供的信息是“总交期大于20天”，这叫右删失。下一次到货和最终收齐也不同：B可能明天到30件，但仍没收齐100件。

本模拟1800张PO，每张有承诺日promised_day和逐次收货事件。原始特征包括供应商、复杂度、季节、历史OTD以及下单时WIP。WIP是尚未收齐的工作量：在一个as-of时点，把之前已下单数量加起来，再减已发生收货；除以5000件容量基准得到wip_load。它不是用事后最终交期倒算的负载。

最终收齐模型在年龄5、10、15天建立快照，只要尚未收齐就保留。快照过程特征包含age、当时供应商WIP、已收比例received_fraction、已到货次数stage、复杂度、季节、下单时可知历史OTD。已收30件的比例是30÷100=0.3，不是“完成30%的时间”。WIP按快照as-of重算，只看那时已发生事件。

### 第四步 实际拟合P50和P90 不把完成样本偏差藏起来

本补课实际用scikit-learn的GradientBoostingRegressor，loss='quantile'，分别拟合α=0.5和0.9。不是调用了LightGBM。目标y是“从快照到收齐还剩几天”，不是从下单起算的总天数。总预计收齐日=asof+预计剩余天数。

分位数损失也叫pinball。设预测q，实际y，误差e=y−q：

ρₐ(e)=αe（e≥0时）；ρₐ(e)=(1−α)(−e)（e<0时）。

以P90为例α=0.9。实际12天而预测10天，e=2，损失0.9×2=1.8；实际8天而预测10天，e=−2，损失0.1×2=0.2。低估长等待被罚得更重，因此模型愿意预测得更靠右。P50两侧权重都是0.5。

每个分位数在验证块比较树深1、2、3，固定120棵、学习率0.05，冻结后测试。训练使用已成熟的历史批次：释放日0至179且截至239已知收齐；验证240至279截至339成熟；测试340至359截至419成熟。模型和参数最晚339日冻结，360日评分不读取其后的测试答案。训练同时覆盖season=0与1；验证是season=0，最终测试是新一轮season=1，明确检验跨季预测。训练、验证、测试快照为2693、597、300行。同一PO的多个快照不能跨块。本模拟最大完成时长短于成熟缓冲，所以这些成熟批次没有未完成样本被偷偷丢掉。现实长尾可能超过60天，届时这个保证失效，普通分位GBDT不能直接处理“只知大于20”的标签。

两条分位模型可能交叉，即P90<P50。本程序报告交叉数，再把较小值作为P50、较大值作为P90，这是简单单调修复，不是证明校准已经正确。测试同时报告pinball和覆盖率“真实剩余天数≤预测分位”的比例。覆盖率接近目标只是必要诊断，还要分供应商、年龄、季节看。

特别注意：本轮重新划定合法时间块后，全部300行测试快照的原始P50覆盖率为58.67%，高于本教材45%至55%的粗警戒带，仍标记不合格；原始P90覆盖90%位于85%至95%的粗警戒带。300行中仅135行满足当前模型的输入支持检查，CSV另外列出支持标志；这135行的P50/P90覆盖为65.19%/94.81%。不能把整体测试结果当作所有订单都可输出承诺的证据。警戒带只是学习用诊断，不是统计置信区间或生产验收标准。离散天数的分位数还可能跳跃：若70%到货在第2天、30%在第3天，第2天可作为P50，覆盖自然为70%，不能为了凑50%随意拆分。上述警戒带只是提醒进一步检查，不是数学定理。不能因为代码测试通过，就把这个模型作为可靠交期承诺。P90也不等于对每张PO都90%准确，分位保证本身还取决于校准与分布稳定。

### 第五步 未完成PO如何进入下一次到货模型

为了真正利用未结束记录，本项目另训“到下一次收货”的离散hazard模型。每个episode从下单或上一次收货开始，到下一次收货结束；观察截止270日时仍无下次收货的episode右删失，保留已经等过的零标签日，不捏造未来事件。

输入elapsed为该episode已经等第几天，stage为已发生几次收货，remaining_fraction为未收比例；另有episode开始时可知WIP、季节、复杂度、历史OTD。年龄1的hazard与订单总年龄1不是一回事，例如订单第20天刚收到第二批，新的episode从0重新计时。下一次到货模型实际训练GBDT二分类，输入共30641个风险日，包含103个被截断而未到货的episode，绝不是只挑完整记录。

当一张订单已经在本episode等了a天，未来k天内至少收到下一批的概率为：

F(k | 已等a天)=1−∏从j=1到k[1−h(a+j)]。

∏表示把括号里的数连续相乘。若未来两天条件hazard为0.2、0.25，则两天都不到概率0.8×0.75=0.6，两天内至少到一次=0.4。该模型预测的是下一批，不是收齐；批次数量在模拟中固定30、30、40，因此输出下一批事件发生条件下的数量，而不是把概率乘数量冒充已经到货。

在第360日重建131张未收齐PO，保存已收件数、未收件数、上次到货后已等多久、承诺日、下次到货P50/P90和7天到货概率。360日以后的事件仅用于离线标签与事后评估，包括下一批和最终收齐的事后评估文件；不进入360日特征，也不进入本次已冻结模型的训练或选参。最终收齐分位不只检查年龄5至15天，还检查季节、复杂度和stage是否曾在训练中出现，以及WIP、历史OTD、已收比例是否在训练数值范围内。131张中110张拒绝输出（其中76张年龄越界，部分还兼有历史OTD越界），仅21张通过；原因逐行保存。支持检查不是统计可靠性保证，更细条件或分布漂移仍可能失败。

下一次到货模型按stage分别限制elapsed，训练最大值是stage0的21天、stage1的6天、stage2的11天。不能把stage0的21天套给stage1。7天概率仅99张有支持，其余32张留空；P90若在最长15天且不超过本stage支持范围的窗口内未达到0.9，也留空，不填窗口上限冒充P90。po_next_receipt_stage_calibration.csv记录分stage事后校准：P50覆盖依次为26.39%、80%、64.10%，差异需要结合离散天数与样本量解释，不能仅因不等于50%就判定模型错；stage0低于目标尤其值得检查。这些结果保留，不通过调测试来掩盖。

po_full_pending_future_only_evaluation.csv另用未来真值评估360日那21张有支持的最终分位，P50覆盖76.19%、P90覆盖95.24%。它们与300行测试的58.67%/90%是不同分母，不能互换。后验评估不参与360日决策。

### 第六步 OTD与30天收齐不是同一件事

OTD是按承诺日准时交齐。分子是最终收齐日不晚于该PO承诺日的订单数。分母只放结局已经可判定的订单：已收齐的订单，以及承诺日已过仍未收齐的订单。未来还没到承诺日且未收齐，结局未定，暂不进分母。

例子：承诺第20日，实际第23日收齐，虽然30天内收齐，OTD仍失败。承诺第35日，实际第32日收齐，虽然超过30天，OTD仍成功。承诺第20日，到第25日只到60件，也算已知逾期失败；不是因为“已有部分货”就成功。

本项目360日OTD账本有独立状态on_time、late_complete、late_unfilled、unresolved_not_due。默认608单准时，1692单已可判定，OTD=608÷1692≈35.93%；108单未来未到期仍未收齐暂不入分母。数字只是模拟器制造的较紧承诺环境，不代表行业水平。

### 第七步 验收与不能跨越的边界

核对每张PO三次收货合计100；360日已收+未收=100；删失episode没有伪造y=1；训练事件不晚于截止；分位数排序正确；不支持年龄和达不到的P90显示空；部分到货不能标准时收齐；对照承诺日而非固定30天算OTD。

本补课包含两条不同模型：成熟批次的最终收齐分位GBDT，以及带右删失日表的下一次收货hazard。它们不能被说成同一套“已完成全删失纠偏的P50/P90模型”；没有AFT、完整多状态联合概率、数量随机性、共享供应商冲击或采购自动分单。若业务需要完整删失感知的最终交期分位数，应进一步选用支持删失的生存模型，并按相同时间规则比较，而不是从未完成行中硬填一个完成日。

## 交付覆盖与需要如实保留的限制

P14补上真实person-day、年龄哑变量、价格/仓库特征拟合与时间验证。P15补上24h闸门、交期混合、BOM/容量、成本枚举及风险约束超卖；限定单SKU教学政策。R01补上订单特征GBDT；R04补上同一决策日的实物、虚拟供应、订单占用ATP和采购对照。D01补齐原业务特征与本地评分时点契约；D02补齐人审容量、确认/超时状态与因果实验设计，没有线上服务或真实干预实验。L02补齐12格双波动敏感性；L03补上实际分位GBDT、WIP/过程特征、下一次部分到货和承诺日OTD，同时明示成熟训练条件与未完成模型边界。
