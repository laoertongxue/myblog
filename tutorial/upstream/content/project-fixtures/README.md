# P01/P03 可直接操作的数据包

所有输入为模拟数据。仅需Python 3标准库，运行 `python generate_projects.py` 即可重建数据并执行断言。也可不运行代码，直接把input中的CSV导入表格。answers目录是可展开的参考答案，建议做完后再看；数据生成器源代码会揭示注入点，学习时先读README与CSV。

## P01 数据体检

输入：P01/input/demand_dirty.csv（227行=224条原始粒度记录+3条重复），sku_master.csv（8SKU），correction_evidence.csv（修正证据），order_events_dirty.csv（24事件，8订单）。

操作：
1. 按date/store_id/sku_id检查重复，计算“多出的行数”，不是把每组两行都计作两项问题。
2. 与sku_master连接，找不在主数据中的SKU；检查每条单位是否kg。
3. 仅按correction_evidence纠正2未知SKU与2单位错误。证据已表明g是标签错误，数值本来kg；不要通用地把g无条件改kg，否则会误差1000倍。
4. 对同一订单按event_at排序，发现O01在发货后还发生pre_ship_cancel。隔离错误事件，不能擅自改成真实退货或签收。
5. 删除完全重复行，输出清洁日表和质量报告。

答案：3条额外重复、2未知SKU、2单位错误、1状态违规，共8项。清洁日表224行、主键唯一；事件表24行中1条被隔离，保留23条有效已知事件，不臆造O01最终状态。逐行对比answers/clean_demand.csv。这个最小案例用于状态边界，不包含退货/部分发货所有复杂状态。

## P03 查出四种偷看未来

输入：P03/input/demand_180d.csv为2门店×8SKU×180天=2880行，全部kg、无缺货，day1周一；每个日记录在当天23:59可见。每个预测原点视为当天数据已可见之后。固定day1–112训练、113–140验证、141–180历史测试。

另两输入故意错误：features_deliberately_leaky.csv和random_split_BAD.csv。

操作：
1. 根据origin_day检查每个特征的source/fit_end字段不晚于原点。
2. centered_mean_BAD包含目标日与次日；target_value_BAD直接包含目标答案；global_mean_BAD使用全部180天；随机切分会把晚期样本放进训练。
3. 修复为截止原点的滞后/尾部平均，变换器只用训练段拟合；按连续时间切分。
4. 用7天季节朴素做验证单步，原点112–139，对应目标113–140；每条序列28预测，共448行。
5. 单独写固定原点5步评价窗口：原点112–135，共24窗口。每个窗口的未来5个预测都只能用该原点可得信息；本包提供窗口表，不把单步滚动拼接冒充5步。
6. 对照answers中的安全单步账本、24窗口表和四类错误解释，写自己的测试。

预期：所有安全账本train_end_day和feature_cutoff_day≤origin_day；目标=原点+1；5步窗口全部在113–140内。重叠窗口不独立；该测试段称历史测试，非新的盲测。此包提供简单规则基线，不需要安装机器学习库。
